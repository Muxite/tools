# 20261120 Satay CC and DeepSeek Spark prepresentation

Two new Capability Capsules ran through JiuwenSwarm's CCv2 host on a Jetson Orin Nano. A real llama.cpp change passed the bounded single-slot test, a mixed-slot failure drove a restricted release, and actual routed-expert events reached the existing cache replay CC. The Jetson runs qualify this native CPU integration on Granite. The Spark performance comparison is pending.

## What ran on the Jetson

| Capsule | Evidence |
|---|---|
| `engine.prompt_batch_layout` 1.0.1 | Sealed source patch applied to llama.cpp `cf34d311332e362198f0a410c466d1e940287d02`. The 169-token uncached prompt split into ten 16-token batches plus nine tokens, or five 32-token batches plus nine tokens. Across 5-, 32- and 169-token inputs, both caps matched the independently built stock server's greedy IDs and stop reasons. Clearing the cap restored the stock path. An invalid setting failed startup. |
| `observability.expert_route_capture` 1.0.0 | Captured selected IDs for eight fixed decode steps on each of four Granite 3.1 1B A400M Q8_0 requests. All four capture-off/on pairs kept the same generated IDs. Validated 6,144 events across 24 layers and eight selected experts per group. A deliberately missing route row was rejected. |
| Existing `engine.expert_cache_lab` | Consumed the captured events, ran a bounded LRU capacity sweep and evaluated a frozen held-out request. Its hit counts are logical replay outputs. Actual resident bytes, disk reads and inference speed require separate measurements. |

The first prompt-cap implementation co-batched short-request decode with long-request prefill. Its long response reproducibly changed at the second generated token. Stock repeats, the candidate with the cap unset and smaller stock microbatches agreed with stock. The two leading alternatives were separated by 0.009 log-probability units at the common prefix on stock, so the result is consistent with shape-sensitive numerical behavior. Disabling continuous batching in the original candidate preserved the divergence. The revised release restricts the cap to one configured slot. The original two-slot request then matched independent stock exactly and emitted no cap engagement rows.

The guarded release then passed both caps over 14 exact input lengths from 15 to 257 tokens. A separate cached-prefix fixture processed 178 tokens initially, 36 new tokens when extending to 214, and one token on repetition. The cap accounted for each processed token and produced the same IDs and stops as stock.

The native `factory.evidence` CC retained the failed node and added the guard, route capture and follow-up checks to the existing graph. The final graph reached revision 6. An operator supplied the planner decisions in this run.

## Pick the Spark experiment from evidence

The demo targets DeepSeek V4.1 Flash 1017 GSQ-RCO IQ2_XXS on a 128 GB DGX Spark. The pack occupies 248.84 GB, about 231.75 GiB. Earlier stock llama.cpp warm decode was about 11.4–11.8 tokens/s. The custom streaming branch improved over its own first version and remained slower than stock. At 11.6 tokens/s, a 1.30× decode gain needs about 20 ms/token of net savings. A 1.50× gain needs about 29 ms/token. [Quantized model and layout](https://huggingface.co/ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF/blob/main/README.md) · [DGX Spark memory specification](https://www.nvidia.com/en-us/products/workstations/dgx-spark/)

1. **Use Expert Weight Cache and Expert Weight Streaming to qualify stock first.** Confirm host-backed expert eligibility, real cache engagement and actual memory headroom for the pinned pack. Compare native cache disabled with an admitted byte budget and a fixed CPU-miss share. Native llama.cpp already has `--moe-cache-mib`, `--moe-cache-cpu-share`, a ClassLRU implementation and `scripts/moe-cache-tune.py`. Begin with a short stock screen and use that exact simulator or a longer calibration when its controls fit the contract. Diagnose physical reads and wait separately from logical selected experts.
2. **Use Runtime Event Recorder before adding expert staging.** Start with stock cache counters or trace and fill only the missing measurement. For prefill, try stock batch and microbatch settings on the same prompt and compare time to first token. If tuned stock still spends a material portion of prefill rereading or restaging the same expert slices, give Expert Feed-Forward Block and Expert Weight Cache a bounded shared-staging work order. The Satay cap establishes a scheduling control and a correctness pitfall on a different source pin.
3. **Use Expert Demand Predictor only when it can remove measured wait.** Hold out entire requests. Require lead time, byte bounds, same selected experts and evidence that prefetched slices were ready at use. A higher logical hit rate is a mechanism check. Use matched client decode, time to first token and end-to-end completion for the performance verdict.

Use one short decode fixture, such as 128 input tokens and 64 generated tokens, and one prefill fixture, such as 512 input and 16 generated tokens for screening, then 4,096 input and 16 generated tokens if it fits the runtime budget. Freeze model and source identities, whole-engine memory limits, request text and token/stop checks before the comparison. Verify stock A/A and mechanism engagement first. Confirm a promising change with matched stock and candidate ABBA runs on the target. Record trace overhead with a separate diagnostic run.

For the first cache screen, reproduce the retained DeepSeek stock setup at `9048bad8`. Keep the routed gate/up/down CPU overrides, 99 GPU layers, eight compute and batch threads, context 4,096, batch and microbatch 512, one slot, greedy decoding, drafting off and prompt cache reuse off. Preserve the 96 GiB cgroup limit and 16 GiB host-available guard. Compare cache disabled with one byte budget and CPU miss share zero. A 3 GiB budget is a candidate pending actual memory margin, cache-group geometry and startup engagement. Capture the native MCT1 lookup trace in a diagnostic request. Preserve exact tokens and effective placement in the clean comparison.

**Cross-engine choices.** Unsloth Qwen3.8-Flash-Next Q8_0 is a current shared proxy that naturally exceeds Spark memory. Its six base shards total 188 GB, and Strata estimates about 136 GB for full expert residency and documents SSD fallback. The smaller common file is Unsloth Qwen3.6-35B-A3B MTP UD-Q4_K_XL. It needs a separately verified effective memory bound to exert storage pressure. Disable drafting in both engines and qualify the exact shard hashes and effective placement before comparing either model on Spark.
