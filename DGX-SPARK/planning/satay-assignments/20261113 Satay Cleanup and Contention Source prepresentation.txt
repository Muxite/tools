Is contention really a problem? Yes, and there's measured evidence

- Memory is the main issue. The model is a 22 GB file on a board with 7.4 GB of RAM. The engine relies on the parts of the model already held in memory as cache. Anything that reads or writes lots of data, such as copying a 580 MB zip, loading another Docker image, or a compile, pushes those parts out. The engine then has to read them back from disk.
  - A run that started with nothing cached measured 1,290 ms/token, against about 711 for the same engine with a warm cache: about 80% slower from cache state alone.
  - Today's live pair shows the same effect: model load took 67 s for the first run and 51 s for the second, because the second ran after the first had already pulled the model into memory.
- The disk is shared. During generation the engine reads about 0.2–0.3 GB from disk per token. File transfers and Docker image loads compete for that same disk.
- CPU is limited. There are only 6 cores. The fill feature runs 16 reader threads, and a compile wants every core.
  - On 10 Nov a lab run was thrown out because a C++ build was compiling at the same time. The memory watchdog also tripped on that run.
  - That's why builds and GPU runs now share one exclusive queue, and every run records whether anything else was competing.
  - Even the idle queue worker took about 45% of a core.
- Noise sets what you can detect. Run-to-run variation on this machine went from about 1.7% to 3.4% between 11 and 13 Nov. Because the significance threshold is based on that variation, it doubled too. That's why several real 8–12% gains came out "null".

A sentence you can use: "On an 8 GB board running a 22 GB model, the engine depends on what's already in memory and on disk bandwidth. Screen recording, builds or file transfers push the model out of memory and compete for disk and CPU. We measured up to about 80% slowdowns from cache state alone, and a run spoiled by a concurrent compile. So timed results must run with nothing else on the machine, and capture happens afterwards from the logged evidence."
