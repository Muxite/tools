# Five-to-eight-minute demo

## Recommended story

The primary work is [empirical system discovery](campaign-discovery.md), including real inference improvement. Select the few live capabilities from actual campaign value. The image-delivery sequence below is one possible 5–8-minute presentation, not the campaign's acceptance criterion or a fixed CC list.

**Agent uses an engine-delivery CC/tool → builds the inference-engine image → produces identified handoff → lab executes it → target sandbox crashes while evidence/control survive.**

This combines the two proposed demo routes without making the engine itself a CC. If integration time is short, select a genuinely useful finite CC from the campaign plus a real exported engine image and honest receiver acknowledgement. Do not manufacture completed lab execution or abandon the improvement campaign merely because this narrow demo works.

| Time | Live action | What it establishes |
|---|---|---|
| 0:00–0:45 | State coding sandbox, image and test sandbox boundaries | Audience understands ownership and failure domain |
| 0:45–2:00 | Actual agent discovers/invokes the builder-side tool/CC, reviews source/model facts and runs cached build | Agent uses real capability and produces runnable engine image |
| 2:00–3:00 | Inspect release identity, archive hash, build receipt and generated YAML | Product can be handed to another machine without a mutable tag |
| 3:00–4:30 | Lab side acknowledges requirements, stages verified image and starts a short test | Real receiver/executor integration if actually available |
| 4:30–6:30 | Controlled test-sandbox stop; show external status and retained logs/trace segment | Failure does not erase completed work or kill test control |
| 6:30–8:00 | Confirm old work stopped, run new attempt or show prepared recovery result, open evidence manifest | Recovery and coverage are inspectable; attempt IDs remain distinct |

Prefetch weights/dependencies and build expensive CUDA layers before the workshop. The live cached build is still a real build, with its own logs and resolved output. Label any previously collected traces/recovery runs with their original attempt and time. Recorded evidence supplements, not impersonates, a live action.

## Necessary before rehearsal

- Exact M1 demo branch base and isolated development checkout.
- Real engine source/recipe and actual Granite model/input identities; no dependency on a successful optimization.
- Builder-side CC/client can run on the chosen AI4R version; CCv2 is not present in the inspected M1 base.
- Separate coding/test sandboxes and external evidence/controller boundary qualified by their owners.
- Receiver agreement: accepted/rejected/needs-information is different from executed/passed.
- One bounded normal test, one controlled crash fixture, stop confirmation and raw evidence.

## What we can claim now

Research/source collection and portable package integrity only. Historical Docker smoke receipts remain historical. No current demo, host, sandbox, CUDA, model, profiling or crash test has passed here.
