# 2605.27922 · Harness-Bench: Measuring Harness Effects across Models in Realistic Agent Workflows

Yao, Tan, Liu et al. · Peking University + Qiyuan Tech · arXiv v1 27 May 2026 · 16 pp
Read: body p1-14 this session (all appendices)

## Summary
Makes the **harness** the experimental variable instead of the model. 106 sandboxed
offline tasks, 6 configurable harnesses × 8 model backends, all sharing task, budget,
timeout and evaluator while each harness keeps its native prompting, tool interface,
state policy and recovery. Across 5,194 trajectories the harness moves the aggregate
score by **23.8 points** under the same model pool, which is the paper's argument for
reporting capability at the model-harness configuration level.

## How it works (p3-5)
- `Agent = Model + Harness`. Fixed per task: prompt, fixtures, initial sandbox state,
  budget, timeout, evaluator. Varied: model backend and harness. Native to the harness:
  prompting, action format, tool interface, state policy, retry/recovery (Table 1, p6)
- 106 tasks in 8 categories (software engineering 22, workspace/tool 15, data/BI 14,
  knowledge/evidence 13, office 12, vertical 12, long-running autonomy 11, SRE 7)
  (Fig. 2, p4). Each is offline and sandboxed, admitted only on realism, solvability,
  oracle-checkability and integrity (p5)
- Score = Security · Completion · Process, where Security ∈ {0,1} is a hard gate on
  permission violations and Process = mean(Robustness, ToolUse, Consistency) judged from
  the reconstructed trace by a fixed claude-sonnet-4.6 judge (p5, p6)

## Results
- Aggregate by harness (Table 2, p6): NanoBot **76.2**, Hermes 71.2, Moltis 68.8,
  NullClaw 64.4, ZeroClaw 61.4, OpenClaw **52.4** — a **23.8-point spread** on the same
  106 tasks and the same 8-model pool (p7). Codex, reported separately as a model-bound
  coding agent on GPT-5.4, scores 80.4
- Security is 100.0 for every harness (Table 2, p6), so the spread is completion and
  process, not safety violations
- Efficiency is not monotone with score: NanoBot is the best configurable harness while
  using fewer tokens than Hermes, ZeroClaw, NullClaw and Moltis (68.7K vs 133-175K) and
  7.3 turns vs Hermes' 22.6 (Table 2, p6)
- **Stronger models are less harness-sensitive**: mean score rises and cross-harness
  variance falls together (Fig. 3, p7). Weak backends are where the substrate matters
- Failure symptoms among failed trajectories (Table 3, p8): contract/format violations
  36.4%, tool/recovery 24.6%, evidence/grounding 14.6%, artifact commitment 11.1%,
  state/continuation 9.3%
- Harness dependence by category (Fig. 4, p13): highest variance in data/BI analytics
  (0.0155), workspace/tool use (0.0130) and software engineering (0.0102); lowest in
  office communication (0.0020) — harness matters where success depends on state and
  artifacts, not on language generation

## Limitations (stated)
- Complete harness configurations are compared, so results are **configuration-level
  diagnostics, not causal decompositions** of individual mechanisms (p4, p9)
- Offline sandboxed only: no live services, user feedback, drifting external state or
  long-term production memory (p9)
- Process scores depend on an LLM judge (p9)

## Relevance
- **Report §3.3/§5 (harness)**: the cleanest published evidence that the substrate, not
  the model, carries a large part of the score. Pair with Claw-SWE-Bench (2606.12344),
  which gets the same result on a hard-verified coding benchmark
- The failure taxonomy maps almost one-to-one onto AI4Research's design claims:
  "contract/format" is the output contract, "artifact commitment" is plausible reasoning
  that never lands an artifact, "state/continuation" is the ledger. 36.4 + 11.1 + 9.3 =
  56.8% of failed trajectories fail at exactly the layer AI4Research formalises
- The authors' own framing, **execution alignment** (p9), is a usable name for the
  property the report calls intent-to-execution integrity
- ⚠ The 23.8-point spread is an average over 8 backends; it does not isolate which
  harness mechanism is responsible, and the authors say so explicitly
