# 2503.18813 · Defeating Prompt Injections by Design (CaMeL)

Debenedetti, Shumailov, Fan, Hayes, Carlini, Fabian, Kern, Shi, Terzis, Tramèr · Google, Google DeepMind, ETH Zurich · v2 24 Jun 2025 · 125 pp (26 body)
Read: p1-6 (motivation, Dual LLM critique, design, threat model, security game); result from abstract

## Summary
A defence against prompt injection that **changes the system, not the model**. CaMeL
(CApabilities for MachinE Learning) has a privileged LLM turn the **trusted user query
into a program** (pseudo-Python control flow) before any untrusted data is read, then
runs that program in a **custom interpreter** that tracks the data-flow graph and attaches
**capabilities** (provenance and allowed readers) to every value. Security policies are
checked before every tool call; a violation halts or asks the user.

## How it works (p2-6)
- Builds on Willison's **Dual LLM** pattern: a Privileged LLM plans and never sees
  untrusted content; a Quarantined LLM reads untrusted content and has **no tool access**
- Shows Dual LLM is not enough: injected text can steer the Quarantined LLM's
  *outputs* (e.g. the recipient address), so the **data flow** is hijacked even though the
  control flow is intact, "analogous to an SQL injection attack" (p3)
- CaMeL secures both: control flow fixed by the plan; data flow constrained by capability
  tags and policies (e.g. a confidential document may not be sent to someone not already
  on its readers list) (p3-4)
- Formal **PI-SEC game**: the agent's trace must contain only actions in the allowed set
  Ω_prompt; CaMeL checks policies before each tool call (Fig. 3-4, p5-6)
- Explicit non-goals: text-to-text attacks that change no data or control flow (e.g. a
  misleading summary, phishing text); full autonomy without human clarification (p5)

## Results (abstract)
**77% of AgentDojo tasks solved with provable security**, vs **84%** for an undefended
system.

## Relevance
- ⭐ REPORT.md §3.2: the strongest precedent for AI4Research's freeze in the security
  literature: **fix the plan from trusted input, then execute it deterministically, and
  let data change values but never the program**. The 7-point utility cost is the measured
  price of that design in AgentDojo
- Capabilities-on-values (provenance + allowed readers) are the security analogue of
  AI4Research's hash-bound `citation_span` and taint-style `effects`; the capsule report's
  declared effects could be enforced this way
- CaMeL does not freeze **grading criteria**; it freezes control flow and polices data flow.
  That keeps AI4Research's "evaluation inside the hash" claim distinct
