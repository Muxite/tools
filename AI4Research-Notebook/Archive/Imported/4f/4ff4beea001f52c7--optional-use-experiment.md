# Optional use-based experiment brief

**A future assignment template, not an instruction to implement now.** Pair it with the current PRD and maintained full design. The frozen condensed design is only a separate experimental treatment if explicitly assigned; these notes never replace either authority.

## Prompt for a future worker

Use one real, bounded intent-compilation and verification task family to investigate whether selected capsule context helps its consumer. Keep the product contract and gate authority fixed. First read the PRD and supplied design; state any missing prerequisite before inventing product behavior.

Choose several related cases that expose the decision, including an ordinary success, a near-neighbor procedure that looks relevant but has an incompatible prerequisite, an unsupported input, and a scientifically valid negative outcome where applicable. Establish expected outcomes before treatment runs, using a qualified human or deterministic reference independent of the tested verifier; blind adjudication to treatment where feasible. Distinguish protocol conformance, task success and scientific validity, and allow indeterminate outcomes. Hold back at least one variant from context authoring and tuning. This is a small diagnostic study, not a general quality claim.

Compare the same model, harness, permissions, environment and declared budget using no extra feed, a focused curated procedure, and selected experience. Add a length-matched irrelevant-context control when feasible; record remaining confounds. Preserve the actual selected material and its source/version. Separate failure to discover context, incompatible binding, incorrect execution, and mistaken assessment rather than attributing every difference to context quality.

Use paired cases across arms, randomize arm/order, isolate fresh contexts and reset mutable state; prespecify seeds where applicable. Keep procedure-vs-baseline and experience-vs-baseline as distinct contrasts. Run repeated attempts with fresh run identities and retain outputs, traces, mechanically checked facts, verifier verdicts and resulting gate decisions. Do not add judge chains or change release policy to make the study pass. Inspect whether the result can actually be consumed downstream, including its schema and executable behavior where required. Report false advancement and false blocking against the independent outcomes, task completion, regressions, time and cost. A schema-valid result alone does not establish semantic correctness.

Deliver a short comparison with representative failures and links to retained evidence. State what decision the observations support, what remains inconclusive, and the next smallest useful experiment. Choose numerical acceptance thresholds only with the experiment owner; do not convert exploratory observations into new M1 requirements.

## Why these controls

SkillsBench v4 explicitly identifies missing length-matched controls and confounded self-generation as causal-attribution limitations; its task-level variation motivates inspecting regressions rather than only aggregate gain. See [full-text §6.1](https://arxiv.org/html/2602.12670v4#S6.SS1) and the scoped [capsule evidence note](capsule-feeds.md).

The independent expected outcomes and fixed gate boundary are our experimental/architectural choices, informed by the [verification evidence](verification-and-rsi.md); papers do not validate this system. No study has been run here.
