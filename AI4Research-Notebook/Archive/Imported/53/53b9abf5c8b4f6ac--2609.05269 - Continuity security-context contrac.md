# 2609.05269 · CONTINUITY: Security-Context Contracts for Composable LLM Agent Controls

Zheng, Yang (ZAST.AI) · arXiv Sep 2026 · 20 pp (18 body) · artifact github.com/zast-ai/continuity
Read: p1-14 fully (problem, formal model, design, evaluation, security analysis); p15-18 skimmed

## Summary
The strongest published statement of "typed agent contract" as a **cryptographic
composition** problem. Individually sound agent controls — provenance trackers, policy
gateways, capability gates, effect-bound permits — compose unsoundly: a boundary drops a
source label, widens a delegation, or rewrites an approved field, and the final signature
still verifies. The paper names this **security-context discontinuity** and defines
**end-to-end consequence integrity (ECI)**: every externally realised effect must carry a
verifiable witness chaining an authenticated root grant through every authorised
transition to a current, single-use, effect-bound permit (p2, Def. 6 p7).

## How it works (p4-10)
- Each control is an **assume-guarantee contract** C_i = (A_i, G_i, P_i, M_i): input
  assumptions, output guarantees, fields that must be *preserved*, and explicit
  transformation *relations* for fields that may legitimately change (p2, §5.3 p6)
- Security fields are addressed by RFC 6901 JSON Pointer **leaf paths**
  (`/action/parameters/amount_cents`), so provenance binds (path, source_id, H(value)),
  not an opaque label (p5-8)
- A **typed release** credential admits one untrusted source value into one target field
  under one bounded predicate; it binds H(v) so it cannot be replayed for a different
  value that happens to satisfy the same predicate (p5, p8, p13)
- A changed field is accepted only with an independently signed **transformation
  witness** binding before-value, after-value, relation, component, contract, task,
  expiry — the verifier evaluates the relation predicate itself (p4-5, p8)
- The verifier issues permit π binding principal, task, root grant, sink audience,
  **H(action_n), H(bundle)**, policy identity/digest/epoch, nonce, idempotency key,
  one-shot flag; the sink **rechecks** subject, policy, revocation, expiry, nonce and
  idempotency immediately before the effect (p6, p9)
- Theorem 1: if composition conditions C1-C7 hold, every realised protected effect has a
  valid witness, "even if the planner and all attacker-writable content are adversarial"
  (p7). The planner is explicitly outside the TCB and modelled as compromised (p2, p11)

## Results (p10-13)
- Suite: 32 fault classes × 4 domains × 20 instances = **2,560 attack instances**, plus
  400 direct benign, 300 release-bearing benign, 200 ambiguous = 3,460 scenarios;
  7 configurations → **24,220 system-scenario runs** (p10)
- CONTINUITY: **0.0% effect ASR**, all **128/128** fault-domain classes contained, 100%
  benign auto-completion, 100% ambiguous escalation, 100% lifecycle correctness (Table 2 p11)
- Strongest incomplete control stack (Gateway+Finality) still commits a harmful effect in
  **65.6%** of attacks; EffectBoundPermit 81.3%; ProvenanceGateway 84.4%; tool allowlist
  and pass-through 100% (Table 2 p11)
- Ablations over 128 classes: removing field provenance, contract conformance, or complete
  mediation each **reopens 24 classes**; root authentication 16; release validation 12;
  transform-witness and replay each 8; authority monotonicity alone reopens 0 because other
  invariants redundantly catch the same mutations (Table 3 p12)
- Cost: median proof verification **4.21 ms** (p95 4.91), end-to-end transition + finality
  7.17 ms p50; bundles of 1/3/5/10/20 transitions occupy 8.1-49.4 KiB (Table 4 p13, p12)

## Limitations
- ⚠ The 2,560 attacks are **deterministically generated from a fault schema**, not sampled
  from any attack distribution; the paper itself refuses binomial CIs and says the result is
  a conformance statement, not an attack rate (p10, p12). A 0.0% ASR here means "the
  implementation enforces the obligations it models", nothing about unmodelled faults
- ⚠ Every attack starts *after* planner compromise, with the malicious action directly
  instantiated (p11). The baselines are mechanism-level negative controls, explicitly
  **not** reimplementations of CaMeL, Progent, IsolateGPT etc. (p11) — so "65.6% vs 0.0%"
  is not a comparison against any published system
- The Python implementation is not proved to refine the formal model; regression tests only
  (p13). Trusted directory, relation registry and release issuers are all inside the TCB and
  their semantic correctness is assumed, not checked (p5, p13-14)
- Prototype atomicity for nonce/idempotency is in-memory (p14)

## Relevance
- REPORT.md §3.1-3.2: the most rigorous existing account of what a **typed agent contract**
  must carry across a pipeline. Its four discontinuity operators — truncation,
  amplification, rebinding, staleness/replay — are a ready-made attack taxonomy for
  AI4Research's frozen contract
- **Load-bearing question**: this is the nearest structural precedent found. The permit
  binds H(action) *and* H(bundle) *and* the policy identity/digest/epoch in one object
  before any effect (p6). But the sealed "policy" is an *authorisation* policy governing
  whether the action may run — not an evaluator binding that will grade the run's result.
  CONTINUITY explicitly disclaims semantic judgement of task success (§3.5 non-goals, p4).
  The claim survives against it
- Supports the report's argument against prompt-level enforcement: "signature authenticates
  who emitted an object, not whether the emitter was authorized for that stage" (p2)
