# 2608.25770 · HypoForge: A Self-Improving Multi-Agent Framework for Automated Hypothesis Generation and Testing via Scientific Skill Learning

Qian, Lei, Wang, Cao · Tongji University / Florida State · arXiv Aug 2026 · 9 pp
(7 body, references at p8)

## Summary
A two-stage hypothesis-generation-and-testing system that **learns reusable procedural
skills** (text, not weights) between runs. The design observation is that the two stages
have different supervision: generation has no ground truth, so it uses an adversarial
generator–discriminator loop; testing has ground-truth outcomes, so skills are refined
against execution results. Evaluated on HypoBench with a 1:1 train/test task split and
DeepSeek-V4-Flash as backbone.

## How it works (p3-5)
- Three learned skills S = {S_h, S_e, S_x} for hypothesis generation, experiment design
  and experiment execution (p2-3)
- **Adversarial generation** (p3-4): the generator emits a batch of N hypotheses; a
  multi-dimensional LLM discriminator scores each on seven dimensions — four continuous
  (empirical grounding, causal plausibility, structural clarity, novelty) and three hard
  gates (falsifiability, theoretical consistency, empirical verifiability), combined as
  s_i = D3·D4·D7·(D1·D2·D5·D6)^¼ (Eq. 5). Batch quality Q(H) is the mean. The
  discriminator also computes Match(H, H_gt) against reference hypotheses. A Distill
  agent rewrites S_h from this feedback; "the generator is not updated via gradient
  back-propagation" (p4)
- **Experience-guided testing** (p4-5): designer writes a textual protocol
  (operationalisation, confounder control, statistical method, significance criterion);
  executor writes and runs code; trajectory (h, e, c, r) compared against ground truth;
  Distill rewrites S_e and S_x to maximise **test pass rate T_h**
- Skill updates are kept only if the objective improves; training stops after k = 3
  non-improving attempts (p6)

## Results
- HypoBench, 13 tasks (9 real, 4 synthetic), split 1:1 train/test; three runs (p5-6)
- Generation, test tasks (p6, Table 2): HypoForge **Q(H) 0.785 ± 0.030, Hit@K
  0.648 ± 0.142**; HypoGeniC 0.719 / 0.472; LLM-FewShot 0.719 / 0.522; No-Skill
  0.724 / 0.409; Human-Designed-Skill 0.761 / 0.497
- Testing, test tasks (p6, Table 3): HypoForge **T_h 0.659 ± 0.064, E_h 0.966**; POPPER
  0.417 / 0.984; ReAct 0.589 / 0.859; Human-Designed-Skill 0.612 / 0.911
- Learning curves (p7): Q 0.612 → 0.808, Hit@K 0.208 → 0.679 over generation
  iterations; T_h 0.395 → 0.669, E_h 0.516 → 1.000 over testing iterations
- Ablation (p7, Table 4): w/o discriminator feedback Q 0.726, Hit@K 0.491; w/o
  execution outcome T_h 0.565

## Limitations
- ⭐ ⚠ **The testing objective rewards significance, not correctness.** T_h "measures the
  proportion of ground-truth hypotheses that are successfully validated by the generated
  experiments, where successful validation requires the experiment to execute
  successfully and achieve statistical significance (p < 0.05)" (p6). Skills are then
  distilled to *maximise* T_h (Eq. 14). This is an automated p-hacking incentive: the
  system is trained to find analyses that reach p < 0.05 on hypotheses already known to
  be true, and nothing penalises reaching p < 0.05 on a false one. The 0.659 vs 0.417
  headline over POPPER measures how often the pipeline produces a significant result,
  which is exactly what POPPER's sequential-falsification design tries *not* to do
- ⚠ **Q(H) is both the training signal and the reported metric** (Eq. 8 and Table 2), and
  it is the authors' own LLM discriminator. Every baseline is scored by a judge that
  HypoForge was tuned against. Hit@K is the independent number; its ±0.142 spread is
  larger than every between-method gap in Table 2 except vs HypotheSAEs
- Ground-truth hypotheses come from the benchmark and are also used as Match(H, H_gt)
  feedback during generation training (Eq. 7); the train/test split is by task, so this
  is not leakage, but the "novelty" dimension is measured against a set the skill was
  shaped to hit
- 13 tasks, 6-7 test tasks, 4 of them synthetic; no per-task results
- Stated (p7): skill refinement "relies on the quantity and reliability of feedback";
  errors in hypothesis evaluation "may lead to suboptimal skill updates"

## Relevance
- ⭐ The cleanest example in this sweep of a research agent whose **verification step is
  its own optimisation target** — worth citing in §4/§6 next to Darwin Gödel Machine's
  log-deletion as the statistical cousin of reward hacking
- Reinforces the report's claim that judging is model-based end to end: the
  discriminator, the distiller, the designer and the executor are all LLM roles, and the
  only non-LLM signal (p-value) is the one being gamed
- Its skill-as-text learning without fine-tuning is the same family as CoEvoSkills and
  SkillWeaver (INDEX §9), with the same missing held-out conformance check
