# Intent: RawIntent and IntentIR · `cc.intent.v1`

**What it is.** The values of two Artifacts:
- the **RawIntent** is the request exactly as it was given, with any attachments stored as Artifacts;
- the **IntentIR** is what the request means: goals, outcomes, constraints, and what is ambiguous, conflicting or unknown.

`decide_acceptance` reads the IntentIR and decides whether to accept it.

**In M1 only the RawIntent is used.** Ingestion writes it; Phase 1 intention compilation is template mapping in control code, with no IntentIR. The IntentIR returns with the Leader Agent test in B2.

**Rules that matter most here:** INV-2 (a repair writes a new IntentIR with `generation + 1`), INV-6.

## What: the core

**Both are [Artifacts](artifact.md).** Intake stores the request as an Artifact of type `raw_intent` (origin `human`), which from B2 is the input of intention compilation (the Leader Agent); that output, like every capsule's, is an Artifact, of type `intent_ir`. The Artifacts carry the envelope and the hashes; the two tables are their values' schemas. So the request text is stored once, and every IntentIR can be traced to its request through its call's Observation.

**RawIntent** (`cc.intent.raw.v1`, the value of a `raw_intent` Artifact)

| Field | Type | Req | From | State | Description |
|---|---|---|---|---|---|
| `text` | `text` | req | B1 | proposed | The request, verbatim. Example: `Explore 4-bit quantisation for our 7B model; the papers are in inputs/.` |
| `attachments` | `list<object>` | opt | B1 | proposed | Files the human attached, and in M1 the `.txt`, `.md` and `.pdf` documents ingested from the workspace input directory |
| `attachments[].name` | `string` | req | B1 | proposed | The file name as given. Example: `quant-survey.pdf` |
| `attachments[].artifact_ref` | `Ref(artifact)` | req | B1 | proposed | The [Artifact](artifact.md) holding it, of type `file` |
| `channel` | `string` | req | B1 | proposed | Where the request came from: `web` (the workbench), `tui` or `cli`. Example: `web` |
| `source_ref` | `object` | opt | B1 | proposed | Ids copied from jiuwenswarm's E2A envelope, so our run can be joined with theirs |
| `source_ref.request_id` | `string` | opt | B1 | proposed | The gateway's request id |
| `source_ref.session_id` | `string` | opt | B1 | proposed | The conversation session |
| `source_ref.user_id` | `string` | opt | B1 | proposed | Who asked, as the gateway identifies them. Example: `u-1029` |
| `source_ref.identity_origin` | `enum(user, agent, service, system)` | opt | B1 | proposed | Whether a person is behind the request. Anything other than `user` means nobody is present to answer a question |

**IntentIR** (`cc.intent.ir.v1`, the value of an `intent_ir` Artifact)

| Field | Type | Req | From | State | Description |
|---|---|---|---|---|---|
| `generation` | `integer` | req | B2 | proposed | 0 for the first attempt; each repair writes a new IntentIR with this number one higher |
| `goals` | `list<object>` | req | B2 | proposed | What the human wants achieved. Each is `{goal_id, statement, source_spans}`. Example statement: `Find a way to quantise the 7B model with little accuracy loss.` |
| `outcomes` | `list<object>` | req | B2 | proposed | What should exist at the end. Each is `{outcome_id, class, description, source_spans}`, where `class` is `information`, `artifact` or `action` |
| `constraints` | `list<object>` | req | B2 | proposed | Limits on the answer. Each is `{constraint_id, category, statement, expression, source_spans}`; `category` is `reg(constraint_category)`; `expression` is IntentIR v3's operator tree |
| `ambiguities` | `list<object>` | req | B2 | proposed | Questions the request leaves open. Each is `{ambiguity_id, question, blocking, source_spans}`; a blocking one sends the run back to the human |
| `conflicts` | `list<object>` | req | B2 | proposed | Parts of the request that contradict each other. Each is `{conflict_id, description, resolution, source_spans, derived_from}`, where `resolution` is `clarify` or `reject`, as in IntentIR v3. The gate decides; the IntentIR only proposes |
| `unknowns` | `list<object>` | req | B2 | proposed | Facts that nobody stated. Each is `{unknown_id, question, kind, derived_from}`; `kind` is `reg(unknown_kind)` |

`source_spans` are character ranges in the RawIntent's `text`, so every item can be checked against what was asked. Which RawIntent it was compiled from, and which capsule and model produced it, are recorded in the capsule call's Observation (`inputs`, `decl_hash`, `model`); the Artifact's envelope `producer` is the runner. They are not repeated in the value (INV-5).

## How: lives elsewhere

| Was here | Now lives in |
|---|---|
| IntentIR v3's schema maximum of 4 on `generation` | policy `repair` |
| `unknowns[].resolution` (which stage resolves it) | `ext.planner` |
| "an `action` outcome widens what the contract may allow" | the [Requirement compilation](../components/request-to-contract.md#requirement-compilation) page |
| what the gate does with a blocking ambiguity | policy `gates` |

## Reuse

| Existing | Where | Verdict |
|---|---|---|
| `E2AEnvelope` | jiuwenswarm `common/e2a/models.py:87` | **adapt**: intake copies its ids into `source_ref` |
| `E2AFileRef` | `common/e2a/models.py:60` | **reuse as is**: each attachment becomes an Artifact's `content_ref` |
| IntentIR v3 and its semantic body | AI4Research `harness/schemas/compiler/intent-ir.v3.schema.json`, `intent-ir.semantic.v1.schema.json` | **adopt**, with these changes: `producer` and `artifact_role` dropped (the Artifact's envelope carries them); `raw_intent_ref` dropped (the call's Observation names the `raw_intent` Artifact in `inputs`, and its `content_sha256` replaces `raw_text_sha256`); `unknowns[].resolution`, required in v3, moves to `ext.planner` (it says how, not what); `generation`'s maximum moves to policy `repair` |
| agent-core controller `Intent` | `core/controller/schema/intent.py` | **do not reuse**: it controls tasks (`create_task`, `pause_task`); it does not say what a request means |
