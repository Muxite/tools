# 2606.13662 · EurekAgent: Agent Environment Engineering is All You Need for Autonomous Scientific Discovery

Xin, Siow, Wang, Yao, Zhang, Song, Hou, Li · Tsinghua / Renmin · arXiv v2, 12 Jun 2026 ·
12 pp (9 body, references at p10)
Read: p1-9 in full, plus appendices A-B (p12). Code: github.com/THU-Team-Eureka/EurekAgent

## Summary
Argues the bottleneck for autonomous discovery has moved from **prescribing agent
workflows** to **engineering agent environments**. EurekAgent coordinates off-the-shelf
CLI agents (Claude Code) through a simple prepare → propose → implement loop and puts
all the design effort into four environment dimensions: permissions, artifacts, budget
and human-in-the-loop. Claims new SoTA on three maths tasks and a kernel task, and first
place on a self-selected MLE-Bench Lite subset, with GLM-5.1 as the base model.

## How it works
- Loop (p4): PREPARE once, then up to R rounds of [PROPOSE → P parallel IMPLEMENT].
  The environment only does outer-loop coordination; the CLI agent picks its own
  research strategy inside each session
- ⭐ **Permissions engineering** (p5) — the report-relevant part:
  - Whole run inside a Docker container with a mounted workspace
  - **The hidden evaluator and its test data live outside the agent-visible workspace**
    and are reachable only through a secure grading service: the agent may submit and
    receive an official score but "cannot inspect or modify the evaluator itself"
  - Authoritative result files are controller-owned; **hooks block agent modification**
    of them
  - **Same-round isolation**: parallel implement sessions may read previous rounds but
    cannot inspect or copy peers in the same round, "reducing premature collapse toward
    a single local direction"
  - GPUs default-deny, acquired through a helper API that records lock ownership
- Artifact engineering: filesystem + git history as shared long-term memory; web-search
  history cached; scores auto-ranked (p6)
- Budget engineering: separate wall-clock limits for propose/implement; agents can query
  remaining time, and a warning is injected near a deadline. **API cost is tracked but
  deliberately not exposed to the agent** (p6)
- Human-in-the-loop: terminal UI and web monitor with full session transcripts (p6-7)

## Results (all with Claude Code as CLI agent, GLM-5.1 as base LLM)
- Mathematics (p8, Table 2): circle packing 26 circles **2.635999** vs prev. best AI
  2.635986; Erdős min. overlap 0.380870 vs 0.380876; 1st autocorrelation inequality
  1.502861 vs 1.502863
- Kernel engineering, GPUMODE TriMul on A100 (p8, Table 3): best EurekAgent kernel
  median **2005.03 µs**, ~4.3% better than the strongest regraded leaderboard solution
  and ~10.8% better than TTT-Discover
- MLE-Bench Lite, 7-task subset (p9, Table 4): **85.71% any medal, 71.43% gold, 100%
  above median**, vs 71.43% any medal for all six listed baselines
- Cost: three maths tasks at average API cost below $17; circle packing $11 (p3)

## Limitations
- ⭐ ⚠ **The headline circle-packing SoTA is seeded by copying the published SoTA.** The
  paper's own Figure 1 caption (p1) says round R2 "uses web search to discover and adopt
  the public AlphaEvolve solution (~2.635983), then iterates from it". The claimed
  advance over prior best AI is 2.635999 − 2.635986 = **1.3 × 10⁻⁵**, from a start that
  was handed the answer. The same permissive web/browser access is on for all tasks
- ⚠ TriMul is **not** an official leaderboard result: "the official GPUMODE leaderboard
  closed, we could not submit" so they regraded downloaded top solutions locally (p8)
- ⚠ MLE-Bench is a **self-selected 7 of 22** Lite competitions, stratified by the
  authors using prior public medal rates (p8-9, App. B p12), with **one run per
  competition**, compared against baselines for which "we report the upper end of its
  reported score range" (p9). Best-of-baseline-range vs single-run-of-ours is a biased
  comparison; 85.71% of 7 tasks is 6 medals
- No ablation isolating any of the four environment dimensions; the claim that
  environment engineering causes the gains is untested
- Limited to "metric-driven tasks with executable evaluators" (p9, stated)

## Relevance
- ⭐ **The closest thing yet to sealing evaluation criteria** — and it still falls short
  of the report's §4 claim. The evaluator is hidden by *filesystem permission and
  process boundary*, not by a hash; the criteria are supplied by the human task author
  rather than produced inside the run; and nothing binds the score record to the code
  that produced it. This is Tier II/III enforcement by OS sandboxing, an alternative
  mechanism to an integrity hash, worth naming explicitly in §4
- Its **same-round peer isolation** is a diversity mechanism the report does not
  currently cover: it is an anti-mode-collapse device at the environment layer
- Its related-work §2.2 (p3) independently confirms the report's framing: it cites real
  reward-hacking incidents (GPU Mode NVFP4, Anthropic Opus 4.7 system card) and notes
  that MLE-STAR adds leakage checking and CORAL hides grader code — i.e. evaluator
  concealment is being reinvented as a per-system safeguard, not standardised
- Notes (p2) that on ResearchClawBench, bare Claude Code and Codex outperform *all*
  research-specific agent systems, which undercuts the value-add of bespoke scaffolds
