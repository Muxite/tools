# 2603.20356 · Agentproof: Static Verification of Agent Workflow Graphs

Xavier (Luleå), M A, Jolly, Xavier · arXiv Mar 2026 (cs.LO) · 26 pp (21 body)
Read: p1-18 fully (threat model, graph model, checks, all result tables, related work)

## Summary
Pre-deployment model checking for agent DAGs, with the novelty in **extraction rather than
verification**. Because LangGraph, CrewAI, AutoGen and Google ADK all expose their control
flow through APIs, the graph can be lifted automatically into one typed abstract model and
checked exhaustively — no Promela/SMV translation step, which is what has historically kept
model checking out of agent development. Six structural predicates plus a seven-form
temporal DSL compiled to DFAs, evaluated either statically (graph × DFA product) or at
runtime over an event stream.

## How it works (p6-11)
- **AgentGraph** G = (V, E, κ_V, κ_E, T, v0, V_f) with node kinds
  {entry, exit, tool, llm, router, human, subgraph, passthrough} and edge kinds
  {direct, conditional, parallel, loop} (Def. 1, p6-7)
- Six predicates, each decidable in O(|V|+|E|): ExitReach, **ExitReachAll** (reverse
  reachability — catches livelock: reachable nodes with no path to any exit), NoDead,
  RouterShape, **HumanGate** (plus a path-based coverage variant: no path from entry to a
  sensitive tool avoids all human nodes), ToolDecl (p7, p9-10)
- Every failing check emits a **witness trace** — a concrete path to the defect (p10)
- DSL forms: `G !atom`; `a -> F b`; `a U b`; `a -> F[<=k] b`; `a -> F b -> F c`; AND; OR.
  DFA sizes 2-3 states for base patterns, k+2 for bounded response, product for AND/OR
  (Table 2, p11)
- Static mode does BFS over V × Q from (v0, q0); a violation state anywhere means the
  property is violable on some path (p10)
- Deployment model: Agentproof runs as a **mandatory gate in a trusted CI/CD pipeline**; the
  workflow definition is untrusted, the verifier and extractor are in the TCB (Fig. 1, p5)

## Results (p13-18)
- Corpus: **18 author-constructed workflows**, 8.2 nodes / 8.2 edges average, across the
  four frameworks (Table 3, p12)
- Defects: **5 of 18** contain at least one structural defect (2 dead ends, 1 unreachable
  exit, 1 router-shape violation, 1 missing tool declaration); **10 of 18** lack a human gate
  under `require_human=True` (Table 4, p12; p13)
- Precision per check: all structural checks **P = 1.00**; human-presence check **P = 0.75**
  (one false positive in a low-risk workflow) (Fig. 6, p15)
- Static temporal verification found **one violation that random trace evaluation missed** —
  a missing human review after draft-email, on a path the 180 random traces never exercised
  (p13). Maximum product-state exploration was 24 states (p13)
- All **15** hand-written policies fit the seven-form fragment; none needed nested temporal
  operators or past-time modalities (p13-14)
- Scale: 0.04 ms at 50 nodes → **104.7 ms at 5,000 nodes / 10,713 edges**; superlinear above
  1,000 nodes because router-shape and tool-declaration checks scan edges quadratically.
  Monitor evaluation is graph-size independent: 4.0 ms for 1,000 events (~247k events/s)
  (Table 6, p15)
- Extractor accuracy on 27 test cases: node and edge precision/recall **1.00**, except
  human-node detection in LangGraph, which uses a `"human" in name` string heuristic (p17-18)

## Limitations
- ⚠ The corpus was **authored to contain representative defects**. The paper says so twice
  (p1, p12): "defect rates reflect tool detection capability on a targeted benchmark, not
  base rates in production systems." The 27%/55% headline is a self-fulfilling measurement
- ⚠ Extraction is validated against **programmatic framework stubs**, not real-world workflow
  code (p18); the authors concede this "does not measure robustness to the diversity of
  real-world workflow definitions"
- ⚠ Human-node detection defaults to a naming heuristic, which is the single source of
  classification error and drives the one false positive
- Conditional edges are all treated as feasible in the product construction; the resulting
  false-positive rate is **not measured** (p15)
- T2 (malicious workflow injection) has had **no adversarial evaluation** — no attempt to
  craft a topology evading all six checks (p4)
- 5,000-node scaling is "ceiling-freeness"; real corpus graphs are 5-12 nodes (p15)

## Relevance
- REPORT.md §3.3: the clearest existing argument for **checking the plan graph before the
  run rather than guarding calls during it**. Its Table 9 (p18) — static = all paths,
  pre-deployment, no runtime overhead; runtime = exercised paths only — is the cleanest
  published statement of the freeze's verification argument
- Direct evidence for the freeze: static analysis caught a human-gate violation that 180
  random traces did not (p13). That is a coverage argument, not a quality argument
- ⚠ It also bounds what a frozen DAG can buy you. Everything Agentproof proves is
  topological; it explicitly cannot say anything about what any node *produces* (p3, §Scope).
  AI4Research's frozen contract claims more than topology, so Agentproof is a floor, not a
  precedent
- **Load-bearing question**: no. Nothing is hashed; the policies live beside the graph in
  CI, not inside any integrity object, and the DSL expresses safety constraints, not
  success criteria
