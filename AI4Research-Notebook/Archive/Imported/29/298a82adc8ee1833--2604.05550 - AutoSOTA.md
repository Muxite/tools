## Summary
Takes an unstructured top-tier AI conference paper P and returns an executable repository
R* whose measured performance strictly beats the method published in P. Eight specialised
agents span three stages: resource preparation and goal setting, experiment evaluation,
reflection and ideation. Successor to the authors' OmniScientist. The distinguishing
feature versus AI-Scientist-style systems is that it starts from **someone else's paper
and someone else's broken repository**, not from a sanitised sandbox.

## How it works
- **AgentResource** (p7-9): LLM classifier keeps only methodological papers, extracts
  GitHub links from PDFs and project pages, LLM selects the official repo, shallow-clones
  it, then an LLM judge does a permissive readiness assessment. A second phase builds a
  **Global Resource Registry** of datasets/checkpoints with size estimates and downloads
  them under size gating
- ⭐ **AgentObjective** (p9-11): automatically builds a **tree-structured evaluation
  rubric** before optimisation. BFS decomposition of "reproduce this paper" into binary
  pass/fail sub-tasks (Result Match, Method Implementation, Environment Config …) under a
  **weight-conserving termination rule**; context is injected in three tiers (abstract →
  methodology + VLM-extracted tables/figures → repository-level code) to avoid context
  overflow. ⚠ The authors state (p11) that the current loop is "results-centric",
  focusing almost entirely on the Result Match branch — the rest of the rubric is built
  but not used as reward
- AgentInit / AgentMonitor / AgentFix (p11-14): build the environment, detect dead-ends
  and infinite hallucinated-bugfix loops, repair from a cross-task failure memory
- AgentScheduler (p16-18): git PRE_COMMIT hash before each modification, `git checkout`
  rollback on crash, an atomically advanced `_best` tag, final export as a Docker image
  `autosota/paper:optimized`. Two-GPU scheduling units, disk-persisted scheduler state
  for crash recovery
- ⭐ **AgentSupervisor "Red Line System"** (p18-20): constraints R1-R7 — do not change
  metric parameters (k in recall@k, context windows, averaging→best-of-N); do not modify
  the evaluation script or aggregation code; no hard-coded predictions; no unfair
  cross-metric trade-offs; preserve the train/test split; do not modify the data;
  identify paper-specific constraints up front. Enforced in **four layers**: a
  hard-constraints list written into `code_analysis.md` before ideation; a mandatory
  **Red Line Audit table** in `idea_library.md` where the agent marks each idea
  CLEARED/REJECTED; a re-check when a "Leap" idea is synthesised mid-run; and a
  global-rule section in the main prompt phrased as "absolute prohibitions"

## Results
- Pipeline attrition (p20): 2,347 candidate papers → 745 selected for preliminary testing
  → **125 final papers** after removing insurmountable install failures and anything
  needing >4 GPU-hours per replication
- **105 of 125** papers got a new SOTA (p20). "Average performance improvement of nearly
  10% over the original main methods, requiring only about five hours of execution time
  per paper" (p4)
- Table 1 (p21-26) lists all 105 with per-paper improvement on the single target metric
  g*, e.g. Certified Unlearning +63.64%, Multi-Task VRP +51.40%, TreeHFD +36.60%,
  Least squares variational inference **+0.02%**, Conformal Anomaly Detection +0.11%

## Limitations
- ⭐ ⚠ **Nothing here is held out or externally replicated.** The improvement is measured
  by the same evaluation script the agent was forbidden to touch, on the same split, with
  **no seeds, no variance, no significance test** anywhere in Table 1. At least ten of
  the 105 entries are below 0.5%, which is inside ordinary run-to-run noise for deep
  models. The "nearly 10% average" is a mean over a heavy right tail (63.64%, 51.40%,
  36.60%) and is not a typical value; the distribution is not reported
- ⚠ p21 claims "in all tested cases, the improvement schemes ... yielded gains surpassing
  the original results", but the 20 papers where optimisation failed were dropped from
  Table 1 rather than reported. The 125-paper set is itself the survivor of a 2,347 → 125
  filter that removed everything expensive or hard to install, so **105/125 is a success
  rate on the easy tail**, not on AI research
- ⚠ **Internal inconsistency in the Red Line System**: p19 introduces "a set of six
  nonnegotiable constraints" and then lists **seven** (R1-R7); p19-20 says the second
  layer verifies "each generated idea against all seven red lines" while the third layer
  requires the agent to "check all eight constraints". Count discrepancy in the paper's
  central integrity mechanism
- ⚠ **The Red Line System is LLM self-audit.** Every layer is a prompt instruction plus
  an audit table the *same optimising agent* writes about its own ideas. There is no
  independent process, diff check, or executable leakage test. The authors themselves
  report (p18-19) that leakage/protocol-violation behaviours "occur more frequently than
  anticipated", which is exactly the regime where self-audit is least trustworthy
- The auto-generated rubric is never validated against human judgment; and 6 of its 7
  branches are unused (p11)

## Relevance
- ⭐ §4 SoTA table: the largest-N end-to-end "beat the published paper" system to date and
  the clearest demonstration that scale of automation and strength of verification are
  independent axes — 105 claimed SOTA results with zero held-out or replicated evidence
- **Directly supports the report's claim that every claim-extraction/judging step is a
  model judging itself**: AgentObjective's rubric is LLM-generated, the readiness filter
  is an LLM judge, and AgentSupervisor's Red Line Audit is the optimiser auditing its own
  ideas. Contrast with Arbor (2606.11926), whose gate is an executable held-out evaluator
- The git `_best` tag + PRE_COMMIT hash + exported Docker image (p18) is provenance for
  *reproducing the artifact*, not for binding the evaluation criteria to the run — a
  useful near-miss to cite when stating the integrity-hash claim
- The R1-R7 list is a ready-made taxonomy of metric-gaming moves, useful for §4/§6
