# 2604.03515 · Inside the Scaffold: A Source-Code Taxonomy of Coding Agent Architectures

Benjamin Rombaut · arXiv v1 Apr 2026 · 42 pp (about 35 body)
Read: body p1-14 and p27-35 this session

## Summary
Reads the actual scaffold code of 13 open-source coding agents at pinned commits and
characterises each on 12 dimensions in three layers (control architecture, tool and
environment interface, resource management). Finding: scaffold architecture is
**spectra, not categories** — five loop primitives compose freely, and 11 of 13 agents
layer more than one. Deliberately reports **no success rates**, on the argument that
SWE-bench numbers cannot attribute performance to architecture.

## How it works (p6-10)
- 13 agents selected from SWE-bench leaderboard literature plus developer adoption,
  split into interactive CLI agents and SWE-bench agents; proprietary scaffolds excluded
  as non-inspectable (p7). All analysed at pinned commit hashes (Appendix B)
- Each claim is grounded in a file path and line number. A post-hoc verification pass
  checked 296 extracted claims: **267 confirmed, 19 corrected** (mostly line-number
  drift), 10 accepted as simplifications (p33)
- Dimensions include control loop type, loop driver, control-flow implementation, tool
  set design, edit format, execution isolation, state management, context compaction,
  multi-model routing

## Results
- Control loops span fixed pipelines to full MCTS with reward backpropagation; **7 of 13**
  use a sequential ReAct loop as the primary structure, and **11 of 13 compose multiple
  primitives** (p2, p29)
- **Tool counts range 0 to 37** yet converge on four capability categories — read,
  search, edit, execute (p29-31)
- **Context compaction shows seven distinct strategies across 13 agents** (p30). The one
  agent with no compaction (mini-swe-agent) simply crashes when the window is exceeded,
  which the author reads as evidence that compaction is not optional (p31)
- Loop driver spans user-driven (Aider, LLM never chooses a tool) to **9 of 13 giving
  the LLM full tool autonomy** (p13)
- Control flow implementation: 8 of 13 use an imperative `while` loop; graph-as-control-
  flow (Prometheus) is qualitatively different in being inspectable, serializable and
  checkpointable by the framework (p13)
- 5 of 13 support sub-agent delegation, through five different mechanisms; OpenCode's
  sub-agents carry **scaffold-enforced tool permissions** (plan agent cannot edit) (p27)
- Converging dimensions are the externally constrained ones (tool categories, string-
  replacement edit format, Docker isolation); diverging ones are the open questions
  (compaction, state management, multi-model routing) (p29-30)

## Limitations (stated)
- **Single-author analysis**, self-verified; independent replication not performed (p33)
- Open-source only; proprietary scaffolds are invisible to the method
- Agents were pinned at commits spanning Jun 2023 - Mar 2025, so the snapshot ages fast

## Relevance
- **Report §3.3/§5**: gives the vocabulary for describing AI4Research's substrate in
  terms an outside reader can locate in other systems, instead of bespoke names
- ⚠ Its most quotable claim for the report is methodological, not architectural: the
  author refuses to correlate scaffold design with SWE-bench success because "different
  agents used different underlying models, and model capability is a larger confounder
  than scaffold design", and because **documented solution leakage in SWE-bench issue
  descriptions makes raw pass rates an unreliable signal regardless** (p10). Cite this
  alongside Claw-SWE-Bench's measured 8.0 pp leak effect
- Also names the sampling-vs-iteration confound (p32): an agent sampling 40 mediocre
  patches can outscore one that refines carefully, and no current benchmark separates
  single-attempt quality from multi-attempt strategy. Directly relevant to how
  AI4Research should report its own verification-loop results
- Argues for architecture-aware evaluation within existing benchmarks — fix the tool
  set and vary the loop, or fix the model and vary the scaffold — which is precisely
  what Harness-Bench (2605.27922) and Claw-SWE-Bench (2606.12344) went on to do
