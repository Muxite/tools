# 2604.01687 · CoEvoSkills: Self-Evolving Agent Skills via Co-Evolutionary Verification

Zhang, Fan, Zou, Chen, … Li, Yu · UIC, MBZUAI, McGill, Columbia, Zhejiang, UBC · COLM 2026 · arXiv v3 10 Aug 2026 · 23 pp (10 body)
Read: body p1-10 this session; earlier close read in `notes/35-coevoskills-self-vs-human.md`

## Summary
Generates **multi-file skill packages** (SKILL.md, scripts, references) rather than
single tools. A **Skill Generator** iterates on a skill; an informationally isolated
**Surrogate Verifier** (a separate LLM session) writes deterministic test assertions
from the task instruction, observable inputs and output artifacts, and returns failure
diagnostics. On SkillsBench, 71.1% pass rate against 53.5% for human-curated skills.

## How it works (p3-7, Alg. 1)
- Task framed as a POMDP whose success criteria are hidden tests R
- **Surrogate reward** R̃ = fraction of verifier assertions passed (Eq. 4)
- **Loop**: while R̃ < 1, the verifier's test suite is frozen and its diagnostic drives
  skill refinement. When R̃ = 1, a **ground-truth oracle** re-runs the skill in a fresh
  environment and returns **only one pass/fail bit**. On a fail the verifier must
  **escalate** its tests without seeing the oracle's content (Eq. 6, 8)
- Isolation: the verifier never sees generator reasoning, skill source or oracle tests
- Budgets: K = 5 oracle rounds, M = 15 repair retries, context cap 0.7; best-scoring
  snapshot kept
- Backbones: Claude Opus 4.6 (Claude Code) and GPT-5.2 (Codex)

## Results
- SkillsBench, 85 tasks, 5 runs (Fig. 4, p8): no skill **30.6%**; CoT self-generation
  30.7%; SkillsBench one-pass self-generation 32.0%; Anthropic Skill-Creator 34.1%;
  **human-curated 53.5%**; **CoEvoSkills 71.1%**
- ⭐ Unverified self-generation is worth about nothing; the authors attribute the gain
  to "the iterative verification loop, not ... the skill-creation prompt" (p8)
- Rounds (Fig. 2, p10): round 2 44%, round 3 63% (passes human-curated), round 5 75%.
  ⚠ 75% and the 71.1% headline are different figures; cite 71.1%
- Cost: **4.1 verification cycles and 2.4 oracle rounds** per task on average (p10)
- Transfer of Opus-evolved skills to 6 other models: +35 to +44 pp (Table 3, p9)
- Beats human-curated skills in 9 of 11 domains; human skills degrade Natural Science

## Limitations
- ⚠ **This summary's own observation [inference from Alg. 1 and §4.1]**: the oracle
  consulted during evolution is the task's hidden test, and evaluation uses the same
  85 SkillsBench tasks. Each skill is therefore selected with up to 5 pass/fail bits
  from the test it is scored on. The paper withholds the test content, not the signal.
  No held-out task split is reported in the body
- Stated: skills evolve from task-relevant background knowledge given at the start;
  open-world evolution is future work (p10)
- Single benchmark (SkillsBench)

## Relevance
- ⭐ **Capsule report**: the positive-direction pair to 2604.00392. Unverified
  generation gives broken tools (96.8% C = 0.00) and worthless skills (30.7-34.1% vs
  30.6%); with a verification loop, the same generators beat human curation. The
  verifier-isolation design (separate session, no access to source or oracle) is a
  concrete admission-test pattern
- **General report**: supports §3.6 and §6. The information-isolation rule matches
  AI4Research's separation between the builder of an artifact and the check that
  admits it. The oracle-bit caveat is an example of why a sealed held-out split
  matters
