# 2608.00808 · Turning Interaction History into Execution State: A Runtime Layer for Long-Horizon Coding Agents (Ledger)

Wang, Xu, Li, Peng, Adams, Hassan, Chen · Concordia, Tencent, Queen's University · arXiv 1 Aug 2026 · 8 pp
Read: p1-4 (method in full); results from abstract and introduction

## Summary
Long-horizon coding agents keep a transcript, but nothing in it says **which observations
still describe the repository now**. Ledger is a **deterministic runtime layer with no
language-model calls** that turns completed interactions into an explicit execution state
(what was observed, what was modified, what was attempted) and uses it at 2 points in
every step. It wraps an unmodified agent.

## How it works (p2-4)
- **Execution ledger** with 3 components, all derived mechanically and reconstructable
  from a saved trajectory:
  - **observation records**: file + line range actually returned (truncated or failed reads
    excluded) + change counters at read time
  - **modification state**: per-file and global change counters; stale if they differ
  - **command records**: normalised command, category (inspect, search, test, modify),
    recency; distinguishes a repeat after an edit (new evidence) from a repeat under
    unchanged conditions (reproduces the old result)
- **Inform path**: before the model acts, a compact state view is rendered at the end of
  the prompt (regenerated, not appended, so prompt caching is not disturbed); marks each
  observation current or possibly stale; "if the ledger cannot determine the status
  reliably, it makes no freshness claim" (p4)
- **Govern path**: before a proposed command runs, check it against the ledger; execute,
  execute with an augmented observation, or **suppress and return the still-valid earlier
  result**
- Design principle: "The language model remains responsible for understanding the issue
  and constructing the repair, while the runtime maintains only facts that can be derived
  mechanically" (p1)

## Results (p1-2)
- All 500 SWE-bench Verified instances, mini-swe-agent: **56.2% → 64.2%** Pass@1 with GPT-5
  mini, **75.8% → 81.0%** with MiniMax M2.5; total cost **−28.9% / −31.8%**
- On OpenAI Codex: **+3.4 points** Pass@1 at **−24.4%** cost
- Ablation: govern drives resolution gains, inform drives efficiency; both together best
- Cites the finding that failing trajectories had already located the right file in 72-81%
  of runs; the extra length is repeated work, not search (p2)
