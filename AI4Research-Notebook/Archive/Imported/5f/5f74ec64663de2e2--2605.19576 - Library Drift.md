# 2605.19576 · Library Drift: Diagnosing and Fixing a Silent Failure Mode in Self-Evolving LLM Skill Libraries

Xing Zhang, Yanwei Cui, Guanghui Wang, Ziyuan Li, Wei Qiu, Bing Zhu, Peiyang He · AWS Generative AI Innovation Center, HSBC · FAGEN@ICML 2026 workshop · arXiv v3 29 Jul 2026 · 9 pp (7 body incl. refs)
Read: p1-9 in full this session (body p1-7, refs p7-8, appendix A-D p8-9)

## Summary
The paper names **library drift**: a self-evolving skill library that grows without
outcome-driven lifecycle management loses retrieval precision, injects stale guidance,
and can push the agent below its no-skill pass rate (Eq. 1, p3). It proposes
**Ratchet**, a single-agent loop in which a frozen LLM writes, routes, curates and
retires its own natural-language skills. Governance has three parts: outcome-driven
retirement, a bounded active cap, and a meta-skill authoring prior (p4). On **MBPP+
hard-100 with Claude Opus 4.7, 100 rounds × 3 seeds**, the Default lifts held-out pass@1
from 0.258 to a late-window mean of **0.584** (gain **+0.328**). A no-injection run gains
+0.002, and a harsh-retirement run falls below the floor (−0.019) (p1, p5). The
SkillsBench "+0.0pp vs +16.2pp" figure appears only as **motivation cited from Li et
al. 2026** (p1). This paper does not measure it.

## How it works (p2-4, p8)
- **Inference**: Task → Router (picks 0 or 1 skill) → Solver (one LLM call, no
  execution feedback, no tools) → Grader → Capsule (task, skill, outcome) (Fig. 1, p2;
  p4)
- **Router**: two-stage retrieval (tf-idf + embedding, K = 10 each), then an **LLM
  gate** that may pick NONE (p8). "Router cutoff: full-bank mode 20" (Table 2, p8).
  ⚠ Its meaning is not explained; presumably the whole bank is shown when it has ≤ 20
  skills
- **Reflection**: a Critic gives each failure a verdict (HELPED / HURT / NEUTRAL /
  INAPPLICABLE + pattern). The Synthesizer writes a skill from each cluster of ≥ 3
  failures sharing a canonical pattern, at most 2 skills per round. The Curator retires
  and enforces the cap (p3-4, p8)
- **Governance (p4)**: (1) retire when n(s) ≥ N_min = 100 and ĉ(s) ≤ −τ = −0.10;
  (2) **active cap C = 50**, evicting the lowest-contribution skill when synthesis would
  exceed it; (3) a meta-skill document constrains how the Synthesizer writes skills
- **Diagnostics (p3-4)**: per-skill contribution ĉ = (successes − failures)/trials,
  attribution verdicts, and router engagement (share of tasks given a skill)
- **Proposition 1 (p4, p8)**: with cap C and threshold τ, expected pass@1 ≥ E[p0] −
  (τ + ε) − Cδ. With the defaults the floor is E[p0] − 0.35, "loose at our scale"
- **Protocol (p4)**: MBPP+ test split (378 tasks) → drop ~273 tasks Opus 4.7 solves on
  all 5 baseline seeds → sample 100 (60 train / 40 eval). All LLM calls use Claude Opus
  4.7; embeddings use Cohere embed-v4 (Bedrock). 9 conditions × 3 seeds (42, 7, 13) ×
  100 rounds. Gain = mean(last 10) − mean(first 10) of held-out pass@1 (Table 1, p5)

## Results (Table 1 p5; Table 3 p9)
- ⭐ **Default**: baseline 0.258 ± .047, peak 0.658, **gain +0.328 ± .018**. 73% router
  engagement, 50 active (at the cap), 89 retired (p5)
- **A1 no injection**: +0.002 (the no-skill floor). The pipeline still runs, with 42
  skills synthesised but never injected (p3, p5)
- **A2 retrieval-only** (no LLM gate, top hit injected): +0.077, 98% engagement (p4-5)
- **A3 no meta-skill**: +0.187 (−0.141 vs Default). The paper calls it "the single most
  valuable component" (p5). p4 says removing it "costs 43%" of the gain and p5 says
  A3 keeps "57%". These agree (0.187/0.328 = 57%)
- **A4 harsh retirement** (N_min 20, τ 0.0): **−0.019 ± .010**, below the floor. The
  bank collapses to 2 active skills and router engagement falls to 19% (p3, p5)
- **A5 / A6 dedup off**: +0.374 / +0.363, slightly *better* than Default (within ±2σ)
  (p5)
- **A7 cap = 100**: +0.317 ± **.110**. The mean is comparable; per-seed gain ranges
  +0.172 to +0.440. "The cap primarily controls variance rather than mean performance
  at this scale" (p5-6, p9)
- **A8 meta refresh every 10 rounds**: +0.372, peak 0.725, at 55% more wall time
  (10.1 h vs 6.5 h) (p5)
- **Cost**: Default ~14.5k LLM calls per 100 rounds, 43% more than A1. Wall time 6.5 h
  vs 2.3 h (p5)
- ⚠ **No ablation removes retirement or the cap entirely**, and no run injects skills
  with no governance. The "bloat" sub-mode (uncapped growth making injections harmful)
  is asserted and attributed to Voyager/ExpeL, but never produced in this paper (p3).
  The conclusion's "stagnates at +0.002 without governance" (p7) refers to A1, which
  is *no injection with governance still running* (p3)

## Limitations
- Stated (p6): one benchmark (MBPP+ hard-100), one model (Claude Opus 4.7),
  thresholds chosen empirically, multi-step agents not tested
- 40 eval tasks and 3 seeds per condition. Baselines vary 0.200-0.300 across conditions
  from sampling noise (Table 1 caption, p5)
- Single-call code generation. The claim that drift is "more acute" for multi-step
  agents is argued, not tested (p1, p6)
- The Prop. 1 bound is loose (floor = p0 − 0.35) (p8)

## Relevance
- Supports: an LLM gate that can decline to inject (choose NONE) beats injecting the
  top retrieval hit (+0.328 vs +0.077, p5). Letting the model say "no skill" matters
- Supports **outcome-driven** removal (retire on measured contribution over ≥ 100
  trials) and warns that removal on thin evidence harms (A4, p3). This is statistical
  retirement after use, **not** a deterministic precondition check before selection
- Weak support for a bounded set: the cap C = 50 bounds the *library's active size*,
  and doubling it changed variance, not mean (p5-6). Per-task exposure is a retrieval
  shortlist (K = 10 each) plus one injected skill (p8)
- Does not test filtering by preconditions or executability at all
