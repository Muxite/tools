# 2606.03056 · SkillDAG: Self-Evolving Typed Skill Graphs for LLM Skill Selection at Scale

Bai, Wan, Zhou, Yu, You, Tsang · Fudan, NUS, CFAR A*STAR · arXiv v2 2 Jul 2026 · 19 pp (10 body)
Read: body p1-10 this session

## Summary
Treats **skill selection** in large libraries as a structural problem. Skills depend on,
specialise, compose with, duplicate or conflict with each other, and embedding
similarity cannot see this. SkillDAG keeps a **typed skill graph** and exposes it to the
agent as tools (`search`, `show`, `propose-edge`, `edit-edge`), so the LLM reads the
structure and **edits it during execution** under structural invariants.

## How it works (p4-7)
- **5 edge types**: `depends_on`, `specializes` (the directed backbone, kept acyclic),
  `composes_with`, `similar_to` (pick one), `conflicts_with` (pruning only, never walked)
- **search** returns 3 separate channels: `matches` (top-K cosine), `neighbors`
  (bounded BFS over the 4 positive types), `conflicts` (1-hop). The agent can drop a
  channel under a tight budget and records why each skill was chosen
- **Cold start**: two embeddings per skill, "what it does" and "what it needs" (an LLM
  imagines invoking tasks, HyDE-style), adaptive cosine threshold, then an LLM
  classifies the pair. `conflicts_with` is left to the online stage, since harm from
  co-use "does not exist until execution is observed" (p6)
- ⭐ **Online edits, propose-then-commit**: `propose-edge` is a dry run showing pair
  history; `edit-edge` commits with a reason and the execution trace. Commits are gated
  **only by the agent's own reasoning**, bounded by 3 structural invariants: acyclicity,
  non-contradiction (no conflict edge alongside a positive edge), and an append-only log
  that supports rollback (p7)

## Results
- Table 1 (p7), MiniMax-M2.7: ALFWorld **67.1%** vs Graph-of-Skills 54.3% (+12.8);
  SkillsBench reward **27.3** vs 18.7 (+8.6). gpt-5.2-codex: ALFWorld tie at 93.6%,
  SkillsBench 36.8 vs 34.4 (+2.4). The aid is large for the weaker backbone and vanishes
  for the stronger one (p8)
- Intrinsic retrieval on identical queries, SkillsBench scale 1000: Ret@K 65.5 → 78.2,
  Ret@1 50.6 → 66.7 (p8)
- Scale: Ret@5 falls only 78.2 → 74.7 across a 10× pool (200 → 2,000 skills) (p9)
- Online edits: +27 committed edges raise ground-truth skills retrieved per query from
  1.915 to 1.984, with zero queries losing a hit, which holds "by construction" since
  edges only enlarge the retrieved set (Table 2, p9)
- ALFWorld held-out transfer: MiniMax test-initial 65.0% vs test-edited 67.1% (p9)

## Limitations
- ⚠ Baseline rewards are **quoted** from the Graph-of-Skills paper, not rerun, and are
  not seed-matched (p8)
- ⚠ The 10× scale robustness isolates the plain `matches` cosine, not the typed edges;
  the authors say so (p9). The measured effect of online edits is small (+2.1 pp
  held-out; +0.07 skills per query)
- Edit quality depends on one episode of the agent's own judgement; invariants are
  structural, not semantic

## Relevance
- **Capsule report**: the closest published design to a capsule library with typed
  relations and governed edits. Its invariants are the same kind of check a capsule
  registry could run on every commit; its "gate only by agent reasoning" choice is the
  point where a contract layer would add a semantic check
- **General report**: supports §3.3 (orchestration). Typed dependency edges with
  acyclicity enforced at commit time parallel AI4Research's scheduler DAG, although
  SkillDAG's graph is a retrieval aid, not an execution plan
