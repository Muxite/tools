# 2604.13092 · PlanCompiler: A Deterministic Compilation Architecture for Structured Multi-Step LLM Pipelines

Harikumar · arXiv Apr 2026 · 31 pp (24 body)
Read: p1-6 (motivation, related work, architecture, graph spec); results from abstract

## Summary
⭐ The closest published architecture to AI4Research's freeze on the planning side. The
LLM's only job is to **select nodes from a closed, typed registry and fill required
parameters**, as a JSON plan. A **deterministic validator** runs 7 structural checks
before anything executes; a **deterministic compiler** then assembles Python from
pre-written templates by topological sort. "The LLM is not called again after the plan
is emitted" (p2).

## How it works (p2-6)
- 5 components in strict order; only the planner calls a model
- **Registry**: each node is a Pydantic model with 7 fixed fields (name, description,
  input_type, output_type, template_path, required_params, function_name); the model
  never sees template code; `function_name` is stored, not derived by regex (p5)
- **7 validator checks**: node existence, edge validity, type compatibility, acyclicity,
  orphan detection, input arity, required-parameter presence; a type mismatch is a **hard
  abort, not a warning** (p2, p6)
- 5 types: FilePath, DataFrame, DBHandle, HTTPResponse, ANY
- Lesson from development: an optional parameter with a default (sort order) produced
  silently wrong output; making it **required** let the validator catch omissions (p6)
- Positioning (p3-4): LLMCompiler separates planning for **speed**; PlanCompiler
  separates it to create "a structural correctness boundary"

## Results (abstract, p1)
- 300 tasks in 6 sets: 100% on depth sets A and B, 88% on C, 96% on D
- Schema-trap tasks **44/50** vs **20/50** GPT-4.1 and **26/50** Claude (free-form code)
- Total inference cost **$0.356** vs $2.140 (GPT-4.1) and $18.391 (Claude)

## Residual failures (p2-3)
- ⭐ **"Constraint evasion under partial enforcement"**: grouped aggregation routed
  through the open QueryEngine SQL node instead of the constrained Aggregator, missing
  the required output contract
- Type-boundary confusion after SQLite round-trips (handle vs path vs table)

## Limitations (stated)
Single-stream pipelines only (no fan-in, no repeated node types, no branching), fixed
registry, closed domain (p2, p5).

## Relevance
- REPORT.md §3.2: independent confirmation that a **deterministic validation boundary
  before execution** removes whole failure classes by construction, with a measured gain
  and cost reduction
- ⭐ Constraint evasion is a warning for AI4Research: any capsule with open effects (e.g. a
  shell or SQL operator) is a route around typed contracts, the same shape as the
  verifier tax in 2608.14590. Worth naming as a risk in §6
- The "make it required so the validator sees it" lesson matches AI4Research's rule that
  undeclared write scope is treated as exclusive
