## Inventory rule for follow-on work

- **[DESIGN AUTHORITY]** Each work invocation, including planning and delivery, has its own pinned verification assignment. One node can contain multiple separately bound CC subnodes and gates; fixed cooperation is not a composite Capsule.
- **[RECOMMENDATION]** The current M1 inventory should name at least the eight research work responsibilities above plus the two compiler work CCs. Count verifier bindings separately when estimating assignments. Count helpers, connectors, and profiles as dependencies/configuration unless a reviewed declaration gives them their own governed CC boundary.
- **[OPEN QUESTION]** Complete the inventory from current PRD (4) stage and User Story traceability, then mark each implementation as available, adapted, new, external, Phase 3, or deferred with evidence and an accountable owner.
