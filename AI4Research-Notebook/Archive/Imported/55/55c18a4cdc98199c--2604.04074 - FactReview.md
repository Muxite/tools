# 2604.04074 · FactReview: Evidence-Grounded Peer Review with Execution-Based Claim Verification

Yue, Ouyang, Xu, Huang, Liu, Zheng, Liu, Pan, Di, Zhang · RPI, Sun Yat-sen, Southeast, HKUST · arXiv v4 16 Aug 2026 · 16 pp (7 body)
Read: body p1-4 (motivation, method) and abstract results. Code: github.com/DEFENSE-SEU/FactReview

## Summary
An **audit pipeline** for peer review: it extracts review-relevant claims from a
manuscript, grounds each in related work and reference checks, and, when code is
released, **executes the repository under a fixed repair budget**. Every claim gets an
evidence record and one of 4 outcomes. It deliberately gives **no accept/reject
recommendation**: decisions stay with human reviewers.

## How it works (p2-4)
- **Parsing and extraction**: MinerU converts the PDF (sections, tables, equations,
  citation anchors, page locations); an LLM with a **fixed claim schema** extracts major
  claims, results, datasets, baselines, metrics, source spans and evidence targets.
  ⭐ "Broad statements … are split so that support for one local result cannot validate a
  broader statement automatically" (p2)
- **Literature positioning**: Semantic Scholar + OpenAlex; claim-conditioned retrieval
  with minimums (≥3 search calls, 3 distinct queries, 10 evidence annotations);
  **RefCopilot** normalises citations and flags unresolved, withdrawn or mismatched
  references (p3)
- **Execution-based verification**: prepare → plan → run → judge → fix → finalize; up to
  K = 3 Run-Review-Fix rounds. ⭐ **Repair allowlist**: dependencies, paths, launch
  arguments, wrappers only; **architectures, losses, datasets, evaluation logic and
  baselines may not be changed** (p3). Execution separates 3 questions: does it run,
  can the metric be recovered, is the value comparable to the claim. A smoke test with no
  claim-linked metric stays **Inconclusive** (p4)
- **Outcomes**: Supported (direct evidence at stated scope) · Partially supported ·
  In conflict (reliable contradiction) · **Inconclusive**; outcome and provenance stored
  separately (p4)
- ⭐ Before any test run the authors **froze the claim schema, prompts, matching
  threshold, retrieval policy, evidence-status rules, execution tolerance and repair
  allowlist** (p4)

## Results (abstract, p1)
- 26 paper-disjoint test papers, **354 human-verified claims**: **84.3% F1** claim recovery
- Same-backend comparison: 4.72/5 overall, +0.74 over a direct LLM reviewer
- **Removing execution evidence changes 17.0% of claim statuses**, more than any other
  single evidence source
- Reviewer study: review time −58%, benchmark-claim coverage 87% → 99%
- Annotation agreement on the claim inventory: F1 0.948, Krippendorff α 0.896 (p4)

## Limitations
ML papers only; execution possible for only 12 of 26 test papers; LLM extraction and
judging throughout.

## Relevance
- ⭐ The closest published system to AI4Research's claim pipeline. Parallels:
  4-outcome closed verdict set with "inconclusive" (AI4Research: 5 incl. `insufficient`,
  `inconclusive`); scope-splitting of broad claims (AI4Research: `scope_comparison` and
  the over-broad-claim gate); repair allowed but evaluation logic frozen (AI4Research:
  `test_policy` inside the freeze hash); pre-registered evaluation settings (AI4Research:
  frozen EvaluationPlan)
- The 17.0% figure is direct evidence that **execution evidence changes verdicts**, i.e.
  literature-only verification (AI4Research's `source_reported` path) leaves a
  measurable share of claims wrongly labelled
- Difference: FactReview extracts claims with an LLM; AI4Research with a regex
