# 2607.23332 · AllocBench: Measuring Online Tool Allocation Capability in LLM Agents

Wang (Daniel), Xu · Yale · arXiv v2 31 Jul 2026 · 24 pp (about 9 body)
Read: body p1-8 this session; earlier close read in `notes/38-allocbench-close-read.md`

## Summary
Asks **when an agent should build a tool**, not whether it can. Building costs budget
now for reuse later, so a good agent waits for a task class to recur before investing.
Frontier models allocate almost optimally when the choice is abstract (keep or pass a
coloured ball) and **lose that ability as soon as keeping requires writing code**.

## How it works (p3-4)
- Stream of T = 60 numeric word problems from N = 8 families; tool budget B = 3.
  3 families are "hot" (0.85 of mass, recur about 13-23 times), 5 are "traps" (1-6
  times). Streams are rejection-sampled so a trap appears inside the first 3 slots
- At each unseen class: COMMIT (build) or PASS. Optimal policy: **pass on first sight,
  build on confirmed recurrence** (Fig. 1)
- **Framing ladder** on identical latent streams: R0 abstract balls; R1 declarative
  keep/pass on real problems; R2 keep requires a non-empty `solve()` (correctness not
  scored); R3 full script construction, tested and rerun
- Metrics: **first-sight commitment rate**; Score = realised utility / hindsight optimum
  (R0-R2 only, so it is not confounded by coding skill)
- 24 seeds; paired within-model comparisons are the primary evidence

## Results
- First-sight commitment, R0 → R3 (Table 1, p6): Haiku 4.5 28% → 100%; Opus 4.8
  **4% → 99%**; GPT-5.4-mini 15% → 88%; GPT-5.6 Sol 24% → 100%
- R1 changes little, so the failure is not maths. **R2 is the break** for 3 of 4 models
  (85-99%) even though code is not graded; only GPT-5.6 Sol holds at R2 (39%) and fails
  at R3 (p6)
- Transcripts: in R0 models reason about recurrence; in the tool frame they fixate on
  the current instance, e.g. Opus: "I'll write a script for this bit-manipulation
  problem type" on the first problem (p6)
- RL (PPO + QLoRA) on Qwen2.5-Coder-14B cuts R0 first-sight commitment 74% → 6% and
  transfers to lexical reskins, but **not to R1**: the learned policy vanishes once a
  numeric problem is shown (p7)

## Limitations (stated)
- Synthetic streams, one budget structure; cross-model comparisons not causal
- One post-training attempt; the post-training explanation is a conjecture

## Relevance
- **Capsule report**: evidence that the decision to create a capability should not be
  left to the model's in-context judgement. A registry-level policy (for example,
  admit a candidate only after recurrence) is external and survives the framing gap;
  prompting and even RL on the abstract task do not
- **General report**: minor. Relevant to §3.6 only as evidence that agents over-build
  when writing code; AI4Research's capsules are authored, not built on demand
