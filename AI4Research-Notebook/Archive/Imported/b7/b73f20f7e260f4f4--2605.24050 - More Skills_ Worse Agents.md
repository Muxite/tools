# 2605.24050 · More Skills, Worse Agents? Skill Shadowing Degrades Performance When Expanding Skill Libraries

Hongwen Song, Song (Vinson) Wei · Databricks · arXiv v2 23 Jun 2026 · 18 pp (10 body incl. refs, appendix p12-17, p18 blank)
Read: p1-18 in full this session (text extract; Figure 1 on p3 rendered from the PDF because its values exist only in the image)

## Summary
As a skill library grows, the agent passes fewer tasks. The paper defines the
**library-induced pass-rate drop** Δ = p(oracle skills only) − p(full library) (p7) and
splits it exactly into **skill shadowing** (Δshd: the agent's invocation pattern shifts
away from oracle-only use) and **context overhead** (Δctx: the same invocation pattern
passes less often under a larger in-context library) (p7, Eq. 10). On SkillsBench with
Haiku 4.5 and Sonnet 4.6, the mean binary pass rate falls from **0.49 with oracle skills
only to 0.28 with a 202-skill library** (Fig. 1, p3), so Δ = **.21** (Table 1, p9).
Δshd = .14 is the only component whose CI excludes zero; Δctx = .07 is positive but not
significant (p9).

## How it works (p4-8, p12-13)
- **Skill** = (name, description, body). Only the name and description are visible at
  selection time; the body is injected into context when the skill is invoked (p4)
- **Oracle set** S⋆(q): skills that each raise the pass rate over no-skill by ≥ τ, with
  τ = 0.04 (p6, p12). In practice S⋆ is the task's **authored bundle** from SkillsBench
  (1-7 skills, median 2). A (task, model) pair is kept only if every skill in its bundle
  clears τ (p12)
- **Invocation events** per trajectory: n = no skill, m = mixed (≥1 distractor invoked),
  o = oracle-only (p6). Δ = Δctx + Δshd exactly, by the law of total probability (p7)
- **Upper bounds**: Lemma 1 bounds Δctx (it assumes conditional pass rates do not rise
  under the full library); Lemma 2 bounds Δshd (p8)
- **Setup**: SkillsBench (88 tasks). **38 (task, model) pairs: 21 Haiku 4.5, 17 Sonnet
  4.6**. Conditions: S = S⋆ and |S| ∈ {52, 102, 202}. **2,545 trajectories** (p8, p12).
  The 202-skill library is the union of all 88 authored bundles after de-duplication
  (p13). ⚠ The paper does not say how the 52- and 102-skill libraries were sampled
- Two-stage clustered bootstrap: resample (task, model) pairs, then trajectories
  (p13); 2,000 trials, seed 42 (p14)

## Results
- ⭐ **Headline drop (Fig. 1 p3; Table 1 p9)**: mean binary pass rate 0.49 [.37, .60]
  → 0.40 (52) → 0.34 (102) → **0.28** [.16, .39] (202). Δ = .08 / .14 / **.21 [.15, .27]**.
  This is a **21-percentage-point absolute drop from a 0.49 base**. ⚠ The relative drop,
  which the paper does not state, is about 43%. The abstract's "up to 21%" (p1) and
  "drops by 21%" (p2) mean points, not percent
- **Decomposition (Table 1, p9)** at 202: Δshd = **.14 [.06, .26]**, Δctx = .07
  [−.13, .25]. Shadowing's share = .14/.21 ≈ 2/3; the paper's "up to 68%" is on p3.
  At 52 skills, neither component is significant alone (Δshd .03 [−.01, .07])
- **Context overhead is not ruled out**: within oracle-only trajectories, pooled binary
  pass falls .52 → .45 (Table 7, p15). The paper calls context overhead "real but our
  sample size is too small to confirm it" (p9). Upper bound Δctx_sup stays ≤ .08 pooled,
  with no CI excluding zero; Δshd_sup = .24 [.09, .46] at 202 (Table 6, p14)
- **Two distinct failure modes (Table 10, p17)**. Haiku's oracle-only share falls
  80.9% → 29.3% and no-skill rises 19.1% → **65.9%** (**abandonment**). Sonnet's
  oracle-only share falls 97.5% → 81.4% and mixed rises to 14.0% (**wrong selection**).
  Pooled wrong-selection rate πm at 202 is only **.09** (Table 9, p16). ⚠ Most of the
  pooled "shadowing" shift at 202 is into *no skill invoked* (38.5%), not into
  choosing a wrong skill (8.9%) (Table 2, p9)
- **Per model (Tables 4-5, p14)**: Haiku Δ = .26, with Δshd .17 significant at 202.
  Sonnet Δ = .15, but Δctx (.11) ≥ Δshd (.04), with neither significant. The
  shadowing-dominates conclusion is driven by Haiku
- **Shadowing examples (Table 3, p13)**: at 202, mario-coin-counting →
  `video-frame-extraction` first-picked in **51** trajectories; trend-anomaly → 37;
  manufacturing-fjsp → 14
- Intro anecdote (p3): in mario-coin-counting "the agent invokes this wrong one in ALL
  26 trajectories". ⚠ No library size or model is given, and this is not reconciled
  with Table 3's 51
- ⚠ **Count inconsistency**: the text says 2,545 trajectories (p8, p12), but the
  per-condition n in Tables 2/10 sum to 2,576 (p9, p17)

## Limitations
- Stated (p10): 202 skills, two models, one provider (Anthropic). It is open whether
  the result holds at 10× scale or on other architectures
- Only pairs where every bundle skill helps are included, so the sample is selected
  for skill-sensitive tasks (p12)
- Context overhead is underpowered, not shown to be zero (p9). Sonnet's own
  decomposition does not show shadowing dominating (p14)
- Lemma 1 rests on Assumption 1 (the full library never raises conditional pass
  rates), which is assumed rather than tested (p8)
- Trajectory is treated as a black box: only the invocation set and the final output
  are recorded (p4-5)

## Relevance
- Supports: with name and description as the only selection signal, a larger candidate
  set lowers pass rate, mainly because the agent's choice shifts away from the right
  skill (p9). This favours shrinking the set before the model chooses
- Does **not** test any filter. Mitigations (retrieval pre-filtering, description
  disambiguation, learned routing) are only named as next steps (p10). No
  precondition- or executability-based removal is studied
- Its distractors are *relevant-looking but unhelpful* skills, not skills whose
  preconditions fail. Evidence for removing inexecutable skills specifically has to
  come from elsewhere
- Caution: for Haiku the dominant failure is choosing no skill at all (p17). A filter
  that removes distractors may help that mode only indirectly
