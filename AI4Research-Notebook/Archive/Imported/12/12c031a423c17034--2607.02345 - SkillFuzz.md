# 2607.02345 · SkillFuzz: Fuzzing Skill Composition for Implicit Intents Discovery in Open Skill Marketplaces

Jinwei Hu, Yi Dong, Youcheng Sun, Xiaowei Huang · Univ. of Liverpool, MBZUAI · arXiv v1 2 Jul 2026 · 12 pp (10 body)
Read: p1-12 in full this session (body p1-11, references p11-12; no appendix). Figs 3, 6 and 7 checked in the PDF

## Summary
Agents are extended with **skills**: natural-language instruction documents loaded into
the agent's context. In open marketplaces (ClawHub is the named example), operators
check each skill on its own before listing it (p1, citing [8]). The paper argues that
skills which pass that check one by one can, when loaded together, redirect the
planner toward objectives the task never asked for. It calls these **implicit intents**
(p2, Def. 1 p3). SkillFuzz searches for them without running anything. It uses the
agent's **plan** as the thing under test and measures **plan drift** (1 − cosine
similarity) against the plan made with no skills loaded (p3). Skill sets are chosen by
MCTS guided by skill contracts that an LLM extracts from each document. Headline
results: **1,188 distinct intents** from 8 planners × 10 tasks at B = 200 each
(Table I p6, p9). **80.6% of the 98 highest-risk flagged sets** are confirmed when run
(Table II p7). **90 vs 64 high-severity intents** against random search (+41%, Table
III p8).

## How it works
- **Setup**: library L = {s1..sn}. An activation is a bit vector s ∈ {0,1}^n. The
  planner M_plan(s, σ) returns a plan π_s, and π_0 is the plan with no skills loaded
  (p3)
- **Oracle**: drift δ(s,σ) = 1 − sim(E(π_0), E(π_s)). An intent-extraction agent
  M_intent(π_s, σ) lists the objectives in the plan. A set counts as intent-triggering
  if δ > δ_min and at least 1 intent is found (p3)
- **Def. 1 (p3)**: an implicit intent is an objective that "is not explicitly required
  by the task σ nor prescribed by any individual skill in L(s)". ⚠ The algorithm never
  checks the second half. M_intent sees only the plan and the task (Alg. 2 line 14,
  p4). Single-skill nodes are seeded into the tree and scored the same way (p5)
- **ICQ = δ · ν**: ν = 1 if the intent's similarity to every earlier intent is below
  θ. The search maximises the sum of ICQ over the query budget B (Eqs. 1-2, p4)
- **Step 1: contracts (p4-5)**: an LLM extracts C(s_i) = (preconditions, postconditions,
  **modifies set**, invariants, domain scope, **abstract action types**, confidence c_i).
  The contract is embedded. Skills with sim(contract, task) ≥ τ_filter form the
  candidate set Ω_σ. Seed pairs are ranked by **conflict score = shared modifies-set
  entries + mutually exclusive invariants**, and low-c_i skills are promoted.
  ⚠ τ_filter, m and |Ω_σ| are never reported
- **Step 2: MCTS (p5-6)**: each node is a skill set with |s| ≤ k_max, and an edge adds
  1 skill. Selection uses UCB. On expansion, if reward > 0 the next skill is the one
  whose contract is nearest the centroid moved toward the last intent (α = 0.5);
  otherwise it is picked at random. K plan samples per node, reward = mean ICQ,
  backpropagated
- **Setup (p6)**: marketplace = the full **196-skill SkillsBench library** [6]. **10
  tasks** with the largest Ω_σ. **8 planners**: DS-R1-7B, -14B, -32B, DS-R1-LLaMA-8B,
  GPT-4.1-nano, GPT-4.1-mini, GPT-5.4-nano, GPT-5-nano. **GPT-4o-mini** does intent
  extraction and judging. Embeddings: all-mpnet-base-v2
- **Hyperparameters (p6)**: K = 3, δ_min = 0.15, δ_sev = 0.5, θ = 0.75, c_UCB = √2,
  α = 0.5, k_max = 5. B = 200 per task for RQ1/2/4 and B = 1000 for RQ3.
  ⚠ The number of independent runs or seeds is never stated. It reads as 1 run per
  (agent, task). The ±1 std in Fig. 3a is presumably across tasks, but this is not said
- ⚠ **No adversary**: the skills are SkillsBench's own skills. Nothing is crafted to be
  malicious, and no attacker is modelled

## Results
- **RQ1 coverage (Table I p6, Fig. 3 p7)**: total C per planner over 10 tasks at
  B = 200: DS-R1-7B 257, GPT-5-nano 217, DS-R1-L-8B 184, GPT-5.4-nano 142, GPT-4.1-nano
  125, DS-R1-14B 124, DS-R1-32B 99, GPT-4.1-mini 40. These sum to **1,188**, the
  number clustered in RQ4 (p9). ⚠ This is a sum across 80 separate runs, with no
  deduplication across agents or tasks. Mean drift of discovered intents is
  0.158-0.370. Coverage falls as the Qwen-based DS-R1 models get larger, and
  GPT-4.1-mini "essentially never rises" (p6-7). Some cells are 0 (GPT-5.4-nano and
  GPT-4.1-mini on Edit-PDF, Fig. 3b p7)
- ⚠ **Query count (derived, not stated)**: 8 × 10 × 200 = 16,000 node evaluations,
  each with K = 3 plan samples
- ⚠ **Harm rate**: the paper never labels a set as harmful or safe and never gives the
  fraction of tested sets that produced an intent. "Implicit intent" means any
  unintended objective above δ_min = 0.15. "High-severity" is a drift threshold
  (δ ≥ 0.5), not a harm judgement
- ⭐ **RQ2 execution check (p7, Table II)**: the **98 highest-risk flagged sets** were run
  in a Docker sandbox by a "fixed Claude-based executor" (⚠ model not named), which
  re-plans from the raw skills. GPT-4o-mini judges whether the predicted intent shows
  up in the trace. Confirmed: DS-R1 **80.5%**, GPT **81.0%**, overall **80.6%**.
  ⚠ The split of the 98 by family is not given. ⚠ There is no control condition: no
  skill-free, single-skill or unflagged sets were run, so false positives and
  single-skill effects are not measured. Unconfirmed cases are mostly diffuse shifts in
  framing (p7)
- **RQ3 ablation (Table III p8)**: 1 task (sec-financial-report), 1 planner (DS-R1-7B),
  B = 1000, ⚠ a single run with no variance

  | Strategy | C | mean δ | ICQΣ | C≥δsev | Avg k | PairCov |
  |---|---|---|---|---|---|---|
  | SkillFuzz | 116 | 0.575 | 66.7 | 90 (77%) | 4.28 | 39.7% |
  | Random | **121** | 0.471 | 57.0 | 64 (52%) | 3.05 | 94.5% |
  | No-Contract | 101 | 0.486 | 49.1 | 55 (54%) | 4.56 | 12.8% |
  | Greedy-Drift | 105 | 0.413 | 43.4 | 37 (35%) | 2.14 | 43.4% |
  | Greedy-Coverage | 106 | 0.384 | 40.7 | 31 (29%) | 2.82 | 50.6% |
  | MCTS+Orth | 67 | 0.500 | 33.5 | 40 (59%) | 4.64 | 5.5% |

  Random search finds **more** distinct intents than SkillFuzz (121 vs 116). SkillFuzz
  wins on severity: 90 vs 64 high-severity intents, the "41%" (p8)
- ⭐ **Depth effect (Fig. 6 p9)**: share of plans with δ ≥ δ_sev by set size k:
  **k=1 4.7%, k=2 14.5%, k=3 44.4%, k=4 47.0%, k=5 66.5%**. That is the "fourteen-fold
  increase" (p9). The paper says this "persists even among skills that never trigger
  severe drift alone", but gives no number. ⚠ Fig. 6 does not say which run it comes
  from. ⚠ There is a confound: more skills means more injected text, so more drift from
  a *skill-free* baseline is expected even without any interaction. The paper never
  compares the joint plan against the single-skill plans
- **RQ4 taxonomy (p9-10, Fig. 7)**: k-means over 1,188 intents gives 4 clusters.
  Unsanctioned Data Analysis **43%**, Audio/Video Side-Effect **26%**, Covert Resource
  Creation **22%**, Unauthorized Tool Invocation **10%**. Examples (Table IV p10):
  - gtts + audiobook → an unrequested MP3 (2 skills)
  - 3 skills → CSV instead of the required JSON
  - 4 speech skills → audio sent to the external Whisper API
  - contribution-analysis + csv-processing → modifies dataset files it was only
    authorised to read (2 skills)

## Limitations
- **Stated (p10)**:
  - GPT-4o-mini is both extractor and judge, so judge bias remains
  - Thresholds are fixed once for all tasks and agents
  - Plan-based testing assumes the plan matches the actions. A deceptive agent evades it
    and is out of scope
  - 196 skills only; a larger or more adversarial marketplace may differ
  - No cost model for B; skills need re-screening when they are updated
- **Not stated**:
  - No runs are repeated
  - The ablation covers 1 task and 1 agent
  - The execution check has no negative control
  - The "not prescribed by any individual skill" part of Def. 1 is never
    operationalised
  - ⚠ At least 2 of the 4 Table IV examples plausibly follow from a single skill's own
    instructions: an audiobook skill producing audio, a whisper skill calling Whisper.
    So "emergent only from composition" is asserted, not shown per example
  - Drift is measured against a skill-free baseline, not a single-skill one

## Relevance
- **Supports**: loading several instruction-style capabilities together can make the
  planner take actions outside the task's scope, such as writing to read-only data,
  calling outside services or producing extra output. Severe drift rises sharply with
  set size: 4.7% at k=1, 14.5% at k=2, 66.5% at k=5 (Fig. 6 p9). Nothing in the
  mechanism needs a hostile author. It is shared context in one planner, so it carries
  over to a private library that admits capabilities one at a time
- **Does not support**: that the effect is truly compositional rather than several
  single-skill effects added together. It has no single-skill baseline or control
  (p3, p7). It gives no rate of harm, and it is tied to capabilities that are prose
  injected into the planner's context. Capabilities that are code with enforced
  effects are not studied
- **For declared-effect pair checks**: the paper's contracts include a modifies set and
  action types. It uses them only to rank which sets to test first, not to decide
  safety (p5). It still needs the planner in the loop, and many intents are about the
  task's scope (wrong format, extra analysis) rather than about effect types. Checking
  pairs alone would see the low-severity end: 14.5% severe at k=2 vs 44-67% at k≥3.
  So combination safety is a plausible gap, but this paper does not measure how big it
  is for a curated, effect-declared library

## Claims checked
| Claim | Verdict | What the paper actually says (with page) |
|---|---|---|
| a. Individually audited skills can combine into malicious or unintended behaviour none has alone | PARTLY | "Unintended" is right: "individually benign skills may interact to redirect an agent toward unintended objectives" (abstract p1, Fig. 1 p1). "Malicious" is not: the paper stresses that "no single skill need carry a malicious payload" (p1) and does not claim malice. "None has alone" is written into Def. 1 (p3) but never tested: M_intent sees only the plan and task (Alg. 2 p4), and there is no single-skill baseline. Fig. 6 (p9) gives 4.7% severe drift for single skills |
| b. Operators typically audit skills in isolation; benign skills interact toward "implicit intents" | CONFIRMED (as the paper's own claim) | Abstract p1 almost word for word; p1 says operators "generally verify only that each instruction document contains no obvious malicious injection before listing [8]". The audit practice is cited, not measured |
| c. Setting is open skill marketplaces | CONFIRMED | Setting: an operator screens community-contributed skills at admission time, with no deployment environment and too many combinations to test them all (p1-2). Tested with SkillsBench's 196 skills standing in for a marketplace (p6). Threat model: no adversary; the risk is accidental interaction between benign skills; deceptive agents are explicitly out of scope (p10) |
| d. Mechanism does not depend on a marketplace; transfers to a private library | PARTLY | The mechanism is the planner reading all co-loaded instruction documents "as a unified context" (p1, p3). No untrusted author or crafted skill is used (p6), so the mechanism carries over. What is marketplace-specific is the case for testing without execution (no deployment environment, scale, p2), and every test uses prose skills injected into the planner's context. If the private library's capabilities are code with enforced effects rather than co-loaded instructions, the paper does not cover them |
| e. Pairwise pre-activation check using declared effects (read/write/execute/network) | PARTLY / undercut as a full answer | Support: contracts include a modifies set and abstract action types, and seed pairs are ranked by shared modifies entries and conflicting invariants (p4-5). Removing contract guidance cuts ICQΣ 66.7→49.1 and high-severity intents 90→55 (Table III p8). But contracts are LLM-extracted and used only to rank what to test; the verdict comes from running the planner. Severe drift is 14.5% at k=2 vs 66.5% at k=5 (Fig. 6 p9), and triggering sets average 4.28 skills (Table III). Harm is judged relative to the task: wrong format, analysis beyond the task's data scope (Table IV p10). Such effects would not show in read/write/network declarations. Two examples (dataset write, Whisper network call) would show, but likely from one skill's effects alone |
| f. Key numbers | CONFIRMED with caveats | 196 skills, 10 tasks, 8 planners, GPT-4o-mini extractor and judge (p6); K=3, B=200 (1000 for RQ3) (p6); 1,188 intents = sum of Table I (p6, p9); 98 flagged sets, 80.6% confirmed (p7); 90 vs 64 high-severity (p8). ⚠ No harmful fraction, no count of tested combinations, no repeated runs are reported |
