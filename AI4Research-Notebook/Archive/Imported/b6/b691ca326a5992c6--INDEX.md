## New observations from the benchmark/harness sweep (Sep 2026)
- ⚠ TruthInsightBench: four different coding-agent scaffolds on one frozen model are
  *statistically indistinguishable* (58.4-60.3/100, smallest pairwise p = 0.118, p12).
  A total score in that band demonstrates nothing; report the dimension-level rates
- ⚠ NatureBench's twelve "agents" are nine Claude Code + two Codex CLI + one Gemini CLI
  (p14). Its leaderboard is a model ranking, not an agent-system ranking
- ⚠ Claw-SWE-Bench found that upstream SWE-bench-Multilingual Docker images leaked
  future commits; cleaning them costs Claude Opus 4.7 8.0 pp (84.7 -> 76.7, p12). Treat
  pre-2026 multilingual SWE-bench numbers as upper bounds
- ⚠ EurekAgent's 85.71% MLE-Bench any-medal is 7 author-selected tasks from the 22-task
  Lite split, one run each, with baselines quoted at the upper end of their ranges
  (p8-9). It is not comparable to MLE-bench's 75-competition 16.9%
- ⚠ The model-harness survey's SWE-bench Verified table mixes reasoning settings and
  vendor-reported scaffolds; it says so, and only within-row-family comparisons hold (p17)
- Harness effect is *larger on weaker models*: Claw-SWE-Bench 12.5 pp on GLM 5.1 vs
  27.4 pp on Qwen 3.6-flash (p13); Harness-Bench finds cross-harness variance falls as
  model strength rises (p7). A strong-model demo understates the substrate's value

## New observations from the claim/citation sweep (Sep 2026)
- ⭐ **The report's line "every reviewed claim system uses a model to extract and judge" no
  longer holds in 2026.** Three independent counterexamples: 2605.06635 extracts
  citation-claim pairs with a Markdown AST parser and a backward-attribution rule and calls
  it "deterministic citation extraction" (p2, p5); 2606.19819's verifier is regex + spaCy
  dependency parse + NER with convergence theorems (p6, p9, p11); 2604.08501 states
  "deterministic checks where possible, LLM as semantic engine where language understanding
  is required" and "the LLM never decides what to search, which tool to call, or how to
  plan" (p3, p10). CiteAudit's final arbiter is also a rule-based consistency check (p6)
- ⭐ The honest price of determinism, measured: a pure rule-based splitter (SpaCy-senter)
  gets EPR = 1.0 but atomicity-violation rate 0.52-0.56 and Semantic-F1 0.811 vs 0.88-0.91
  for LLM decomposers (2606.19819 p22-23)
- ⭐ sciwrite-lint splits the reliability cleanly: **98.5% recall with zero false positives
  on the deterministic checks, 60% false-positive rate on the model-mediated ones** (p14)
- ⚠ Synthetic-error benchmarks are not predictive: GPT-5.2 scores F1 0.955 on CiteAudit's
  generated split and 0.331 on its real split (2602.23452 p6-p7). Read every
  injection-recall number, including sciwrite-lint's 98.5%, against this
- ⚠ Human gold is weak here: PhD experts in their own specialty label DRR claims at 60.8%
  accuracy one-shot (2603.05912 p5). "Have a human check it" is not a fallback
- ⚠ Provenance ≠ behaviour change: PaperTrail lowered trust significantly and reliance not
  at all (2602.21045 p13), and cost significant usability (p = .026)
- More retrieval makes grounding *worse*: Fact Check drops ~42% from 2 to 150 tool calls
  (2605.06635 p7-9); GPT-Researcher's accuracy falls 69.1 → 68.3 at higher search depth
  (2603.05912 p9); larger backbones do not localize errors better (2606.02060 p7)

### Findings against the report's central novelty claim
The claim under test: *no reviewed system seals its own evaluation criteria (the evaluator
bindings that will grade the run) inside the run's integrity hash before execution.*
**It survives this sweep.** Nearest precedents, in descending order of proximity:
- ⚠ 2606.26924 p20-21: the specification, including its acceptance criteria, **is
  content-hashed at approval** (spec_hash, SHA-256) and each AC maps to verifying tests.
  But the tests are registered by the agent *during* implementation, the linkage is
  cooperative and audited post-hoc ("detectable but not preventable", p21), and the HMAC key
  is machine-local — corruption detection, not an integrity commitment
- ⚠ 2609.05269 p6, p9: the execution permit binds H(action), H(proof bundle) and the policy
  identity/digest/epoch in one object before any effect. The sealed policy is an
  *authorisation* policy, not a grading rule; §3.5 (p4) explicitly disclaims judging whether
  the task was semantically correct
- ⚠ 2607.06001 p5: bands and decision rule frozen in a public commit chain before the runs
  and applied by a committed analyzer — but committed by a *human*, in git, with nothing
  bound to a run-level integrity object
- ⚠ 2605.06365 p9: the runtime is deliberately *denied* the scoring rubric — the opposite
  arrangement

### New observations made while summarising (sweep 10)
- ⚠ 2609.09898: the report's "24-35% LLM PDDL semantic correctness" (from 2608.14590 p4) is
  in range for Planetarium (0.267 baseline, 0.417 few-shot, p6) but is not a general figure —
  the same pipeline scores 0.842 on AutoPlanBench and 0.067 on PDDL 2.1. Quote a benchmark
  with every number. The LLM critic used as the online acceptance signal agrees with a human
  audit only 13/24 (p7)
- ⚠ 2608.02680: its own ablation shows precision falls 0.928 → 0.403 if the most-recent
  survivor heuristic is replaced by random choice among the same candidates (p10); the
  AppWorld 0.993 is a self-consistency check, not cross-corpus confirmation (p11); and the
  paper's "frozen skill" claim is testimony, not a checkable property (p4)
- ⚠ 2605.06365: the DAG condition receives the dependency graph and the recomputation plan
  while the loop baselines receive neither (Table 3, p12). Not an information-equalised
  comparison; n=3, two tasks, one domain
- ⚠ 2609.05269: 0.0% effect ASR is over deterministically generated faults from the authors'
  own 32-class schema, with baselines that are mechanism-level negative controls rather than
  reimplementations of CaMeL, Progent or IsolateGPT (p10-11). It is a conformance result, not
  an attack rate — the paper says so
- ⚠ 2606.07904: the 100-tool registry, its gold contracts and the 102 tasks are all synthetic
  and author-written, and CMTF exposes exactly one tool per step at 1.000 gold exposure — the
  contract graph is doing the planning (Tables I, IV, V, p6-8). Trace evidence is drawn from
  the gold trajectories, which partly leaks the gold contract
- ⚠ 2603.20356: the 18-workflow corpus was authored to contain the defects it reports; the
  paper states this twice (p1, p12). Extraction is validated against framework stubs, not
  real workflow code (p18). No adversarial evaluation of its injection threat model (p4)
- ⚠ 2606.26924: the permission-scope headline (<1% of agent configs) rests on a fragile
  parser with n=31 true positives (p30); conformance N=10/15/20 confirms only that "a hash
  check detects a changed hash" (p27)
- ⚠ 2607.06001: the pre-registration chain is git commit ordering inside an
  author-controlled repo, with no external time-stamp anchoring (p5, p11). Two of six
  predictions returned non-verdicts and one failed — the honest cost of a real freeze

## New observations from the §10 sweep (not stated by the papers)
- ⚠ EurekAgent: the circle-packing SoTA is seeded — its own Fig. 1 caption (p1) says round
  R2 web-searched and adopted the published AlphaEvolve solution before iterating; the
  advance over prior best AI is 1.3e-5. MLE-Bench is a self-selected 7-of-22 subset, one
  run each, compared to the *upper end* of baselines' reported ranges (p9)
- ⚠ Arbor: p5 says E_test is not used as an exploration oracle, but Alg. 1 line 11 (p7)
  calls E_test every coordinator cycle (default 20) and merges on improvement, so the
  "held-out" headline is a max over ~20 test evaluations. Table 2 reports no variance
  although §5.2 promises Avg@3 ± sd; MLE-Bench baselines are quoted, not rerun, on
  different backbones
- ⚠ AutoSOTA: no seeds, variance or significance anywhere in Table 1 (p21-26); ten-plus
  gains are under 0.5%; the 125-paper set is the survivor of a 2,347 → 745 → 125 filter
  that removed every hard-to-install or >4 GPU-hour paper. The Red Line System is
  introduced as "six" constraints, lists seven, then refers to "all eight" (p19-20), and
  every layer of it is the optimising agent auditing its own ideas
- ⚠ StatefulDiscovery: Evidential Support is *lower* than the raw coding agent (3.76 vs
  4.22, p7); the p2 intro is duplicated with conflicting headline figures ("23% more" vs
  "6.25pp more")
- ⚠ HypoForge: the testing objective T_h counts a hypothesis as validated only when the
  experiment reaches p < 0.05 (p6), and skills are distilled to maximise T_h — a built-in
  p-hacking incentive. Q(H) is both the training signal and the reported metric, scored
  by the authors' own LLM discriminator
- ⚠ AutoKD: the 65.9% preference rests on four human raters with Fleiss' κ 0.112 overall
  and negative on two of three datasets (p6, Table 2); the compared set is the top-10 of
  1,367 insights, Hungarian-matched to gold claims for "the most favorable pairing" (p5)
- Report claim check: (a) *no system seals its own evaluation criteria in an integrity
  hash* survives — EurekAgent hides the evaluator by OS boundary, not hash, with
  human-supplied criteria; 2605.08956 (p8-9) recommends exactly this mechanism as
  unbuilt. (b) *strong at generating, weak at checking* is partially challenged by
  Arbor's executable held-out gate but reinforced by SAEScientist-Bench (p8) and the
  68% evidence-ignored / 26% belief-revision figures cited in 2605.08956 (p6). (c)
  *every claim-extraction system uses a model to judge* is partially contradicted by
  AutoKD's deterministic statistical DSL for validity (p6); model judgment remains for
  novelty and faithfulness
