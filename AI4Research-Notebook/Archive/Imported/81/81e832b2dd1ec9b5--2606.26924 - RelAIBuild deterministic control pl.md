# 2606.26924 · A Deterministic Control Plane for LLM Coding Agents

Madatha (Happiest Minds, AIP CoE) · arXiv Jun 2026 · 45 pp (41 body)
Read: p1, p3-4 (thesis, contributions, evidence map), p9-13 (architecture, supply chain),
p19-22 (phase machine, AC traceability, trust boundary), p27-31 (conformance + prevalence)

## Summary
Two things stapled together. (1) A prevalence study of **10,008 GitHub repositories** showing
that agent configuration files — CLAUDE.md, .cursorrules, AGENTS.md — behave as an
**undeclared, ungoverned supply chain**. (2) Rel(AI)Build, a deterministic control plane
*above* the harness: SHA-256 content addressing, HMAC-stamped lockfiles, append-only
hash-chained audit logs, tiered permissions enforced before LLM invocation, and an
eight-phase state machine with requirement→file→test traceability. The word "deterministic"
is load-bearing on purpose: "a non-deterministic component cannot serve as a trustworthy
control for another non-deterministic component" (p3).

## How it works (p10-22)
- Three planes: Authoring & Distribution (content-addressed registry), Compilation (one
  canonical Markdown+YAML definition → seven IDE targets), Runtime-Governance (deterministic
  CLI/MCP helpers that advance phase state and update the trace) (p9-10)
- Install pipeline: fetch → recompute SHA-256 → abort on mismatch → 13-pattern credential
  scan → write transformed files → HMAC-SHA256 stamp over serialised lock data → append
  {action, user, ts, details} + SHA-256 to the audit log (Fig. 3, p13)
- HMAC key is **machine-local, derived from the lockfile path** by default — detection of
  accidental/automated corruption, not adversarial tamper-proofing. An organisational
  signing key is named as an upgrade path and is **not implemented** (p12)
- Phase machine (0 Spec, 1 Design, 3 Implement, 4 Test, 5 Review, 7 Security, 8 Finalize)
  with three hard invariants: phase n cannot start before n−1 ends, ending an unstarted phase
  is blocked, auto-fix loops capped at 3 iterations. Four HITL gates (p19-20)
- **Requirement→file→test traceability**: `trace.json` records, per acceptance criterion, the
  implementing files, tasks, verifying tests and status. **"The specification is
  content-hashed at approval"** (`spec_hash`, SHA-256). A spec-drift check diffs the working
  tree against the phase-start commit and flags any file outside every AC's registered scope
  as scope creep (p20-21, Fig. 6 p21)

## Results (p27-31)
- Conformance: **237** canonical definitions compiled cleanly across 7 targets; all **10**
  integrity-tampering cases aborted at the SHA-256 gate, all **15** over-privileged tool
  declarations failed compilation, all **20** blocklist strings triggered (p27)
- Prevalence (n = 10,008 repos, 9,357 orgs, 33,620 files, 6,145 agent-config files):
  - **10.06%** of tracked config paths are exact SHA-256 duplicates across ≥2 non-fork repos
    (425 content groups, 3,075 instances); **75.51%** of clone pairs cross organisational
    boundaries (66,839/88,517) (Table 10, p30)
  - **58.45%** of agent-config files have exactly one lifetime commit (CI: 57.22-59.68%);
    74.26% have ≤2. GitHub Actions workflows: median 7 commits, 14.07% single-commit
    (Tables 10-11, p30-31)
  - Age-normalised: 0.4 commits/month for agent configs vs **0.6** for CI/CD workflows in the
    same repos — the gap narrows but persists (p30)
  - Explicit permission scopes: **0.5%** of agent configs (31 true positives / 6,145) vs
    **33.39%** of Actions workflows (8,158/24,436) (p30-31)
  - Only 8.45% of repos contain any agent config at all (p28)

## Limitations
- ⚠ The author's own evidence map (Table 1, p4) concedes the conformance tests establish only
  that "hand-written detectors match inputs constructed to be detected, and that a hash check
  detects a changed hash" (p27). N = 10/15/20 injected violations. No developer-outcome or
  field-effectiveness data exists
- ⚠ The permission-scope finding rests on a **fragile regex parser with n = 31 true
  positives** and 6 manually excluded false positives; the author labels it indicative, not
  definitive (p1, p30)
- ⚠ **The trace linkage is an honour system.** AC→file linkage requires the agent to call
  `trace-update`; a prompt-injected or non-compliant agent that edits files without calling
  it surfaces as a scope-creep warning at the *next* drift check — "detectable but not
  preventable before the edit lands" (p21). The abstract repeats this: "trace linkage is
  cooperative and auditable post-hoc, not pre-execution enforced" (p1)
- ⚠ Compilation preserves *declaration*, not enforcement: Codex, Windsurf, OpenCode and Kiro
  have "little or no runtime permission enforcement at the agent-definition level" (p22)
- Single-commit prevalence is confounded by file age (median 4 months vs 17 for Actions);
  the author normalises but the corrected gap is small (p31)
- 3.59% ingestion failure with no per-repo failure logs retained (p29)
- DRIFT vignette is N = 1, governed arm only (p27)

## Relevance
- REPORT.md §3.2-3.3: the strongest empirical case that **agent configuration is unmanaged
  infrastructure**. 10.06% exact cross-repo duplication with 75.51% crossing org boundaries
  and 0.5% permission-scope declaration is the prevalence evidence the report's contract
  layer has been missing
- **Load-bearing question — the nearest counterexample found.** `spec_hash` content-hashes
  the specification, including its acceptance criteria, **at approval**, i.e. before
  Phase 3 Implementation runs, and `trace.json` binds each AC to verifying tests. That is one
  hash covering the plan and the criteria, before execution. Three reasons it does not
  falsify the claim: (a) the hash covers the *AC text*, not the evaluator bindings — the
  verifying tests are registered *during* implementation by the agent, not sealed at
  approval; (b) the binding is cooperative and audited post-hoc, so nothing about grading is
  cryptographically committed against the run; (c) the HMAC key is machine-local, giving
  corruption detection rather than an integrity commitment. **The claim survives**, and this
  is the precedent to name and distinguish
- Its determinism thesis (p3) is the same argument AI4Research makes for the frozen contract,
  stated independently and one level lower in the stack
