# 2606.24530 · NatureBench: Can Coding Agents Match the Published SOTA of Nature-Family Papers?

Horizon Research / Frontis.AI / Tsinghua · arXiv v2 6 Jul 2026 · 35 pp (about 21 body)
Read: body p1-18 this session

## Summary
Moves the paper-derived benchmark from *reproduce* to *beat*. 90 containerised tasks
built from Nature-family papers; the source method is stripped by an information
firewall, and the agent is scored by a SOTA-normalised relative gap against the paper's
own reported number. The strongest of twelve agent configurations clearly beats the
published SOTA on **17.8%** of tasks and merely matches it on 47.8%.

## How it works (p4-12)
- **NatureGym** pipeline: filter → acquire data → build task package, each stage
  review-gated. ~5,500 crawled papers → ~2,500 research articles → ~200 after
  three-level filtering → ~180 after data verification → ~160 built → **90** after
  evaluation-time calibration (Table 3, p8)
- Package: agent-visible `problem/` (README, data description, inputs) vs hidden
  `evaluation/` (evaluator.py, ground truth) plus per-task Dockerfile and the paper's
  SOTA anchors in metadata (Table 1, p6)
- Metric: gᵢ = dirᵢ·(mᵢ − m^sota)/|m^sota| on one designated primary metric per
  instance; **Surpass-SOTA** is g > 0.1, **Match-SOTA** is g ≥ 0 (p12). 81 distinct
  primary metrics across the corpus, mean 3.7 instances per task (p11)
- Protocol: 4-hour wall clock, one GPU sized to the task (3 CPU-only, 70 on a 3090/4090,
  17 on an A800), **web search disabled**, iterative submissions to a host-side scorer,
  plus a post-hoc Claude Sonnet 4.6 validity judge for fabrication and feedback gaming
  (p12-13)
- Calibration used a reproduce mode (agent given the source paper) to separate package
  defects from genuine shortfalls: **45 tasks dropped, 17 repaired** (p9)

## Results
- Surpass-SOTA (Table 4, p13): Claude Opus 4.7 **17.8%**, GLM-5.2 and Gemini 3.5 Flash
  15.6%, GPT-5.5 14.4%, down to MiniMax-M2.7 at 1.1%
- Match-SOTA: Claude Opus 4.7 **47.8%**, GPT-5.5 44.4%, GLM-5.2 41.1% (p13)
- Median all-task gap runs from −0.007 (Opus 4.7) to −0.401 (MiniMax-M2.7); Opus 4.6
  and 4.7 are the only agents with 100% completion and **zero invalid submissions**,
  while GPT-5.5 had 13 shortcut submissions filtered by the judge (Table 5, p14)
- Mechanism analysis over 900 runs: Match-SOTA rate 32.2%; successes come overwhelmingly
  from generic ML engineering — proxy prediction 45.5%, search/tuning 17.6%, pipelines
  11.0%, pretraining 8.6%, i.e. **82.7% engineering-driven**, versus 9.0% method-aligned
  and 8.3% domain-reasoned (Fig. 7c, p16)
- Failures are method-layer 61.1% (wrong method choice 45.1%) and execution-layer 28.7%
  (insufficient budget/time 24.4%); understanding failures only 3.1% (p15-16)
- Domain gradient is shared across agents (Match-SOTA 60.0% relational down to 17.9%
  biomedical; Spearman ρ 0.71-1.00) and cross-discipline tasks are harder (median g
  −0.13 → −0.21) (p16-17)

## Limitations (stated)
- Extreme negative g values are an artefact of the normalisation's small denominators;
  authors audit every extreme task and find no task error but recommend median as the
  tail-robust summary (p18)
- Each task covers only the paper's core quantitative slice, not the full paper (p18)
- Residual leakage is possible because all data are public; mitigated by disabling web
  search and the post-hoc judge (p18)

## Relevance
- ⚠ **Harness is confounded with model here.** Nine of the twelve configurations are
  Claude Code, two are Codex CLI, one is Gemini CLI (Table 5, p14); the paper reports no
  fixed-model harness sweep, so its ranking is a model ranking, not an agent-system one
- The failure decomposition is the useful result for AI4Research: agents do not
  misunderstand tasks (3.1%), they pick the wrong method and stop too early. A
  verification-first system does not obviously fix either
- A newer and harder relative of PaperBench and ScienceAgentBench: same provenance
  (published papers), but the endpoint is the paper's number rather than its rubric
