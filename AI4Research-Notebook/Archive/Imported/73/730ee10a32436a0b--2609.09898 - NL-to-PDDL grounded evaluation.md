# 2609.09898 · Grounded Evaluation and Repair for NL-to-PDDL Problem Generation

Rosa, Santos, Oliveira, Silva, Silveira, Martins (INESC INOV / IST Lisbon) · arXiv Sep 2026 ·
16 pp (8 body) · AAAI 2026 copyright line
Read: p1-8 fully (method, setup, all result tables, discussion, critic audit)

## Summary
The best-sourced current figure for **LLM formal-plan semantic correctness**. The paper's
whole point is that the numbers usually quoted — parseability, planner success — massively
overestimate faithfulness: a generated PDDL problem can parse, solve, and pass VAL while
encoding the wrong initial state, goal, object inventory or optimisation metric. It
therefore separates **operational success** (parse ∧ domain-conformance ∧ solvable ∧
VAL-valid ∧ LLM-critic accepted — computable at deployment time) from **offline
benchmark-reference reconstruction** (renaming-invariant structural match, plus true
semantic equivalence where an oracle exists), and measures the gap.

## How it works (p2-5)
- Pipeline: generate problem.pddl from NL + domain file → parse → static domain-conformance
  checker (objects declared, predicate names/arities, typing) → Fast Downward (classical),
  TFD (time-simple), ENHSP (numeric) → VAL → LLM critic → structured repair feedback →
  regenerate. Max 3 attempts (1 generation + 2 repairs) (p2-3, p4)
- Repair stops on operational success, **unchanged generation**, no actionable feedback, or
  attempt exhaustion (p3)
- Offline only: semantic equivalence via the Planetarium graph oracle (goal completion +
  equivalence), and renaming-invariant structural match over `:objects`, `:init`, `:goal`,
  `:metric` under a consistent object bijection, metric compared strictly on direction and
  canonicalised expression (p3)
- Base model gpt-4.1-mini for generation *and* critic, temperature 0.0; gpt-5.5 and
  opus-4.7 in Appendix C show "the same qualitative pattern" (p4-5)
- Benchmarks: Planetarium and AutoPlanBench (60 instances each subset), plus six curated
  IPC-2002-derived PDDL 2.1 variants, 10 instances each (p4)

## Results (Tables 1-3, p6-7)
Semantic / structural match = the honest "did it mean the right thing" number:

| Setting | Final operational | Final semantic | Final structural |
|---|---|---|---|
| Planetarium baseline | 0.500 | **0.267** | 0.200 |
| Planetarium + few-shot | 0.583 | **0.417** | 0.417 |
| AutoPlanBench (sem. supported) baseline | 0.772 | **0.842** | 0.842 |
| AutoPlanBench + few-shot | 0.750 | **0.714** | 0.714 |
| AutoPlanBench (unsupported) +FS | 0.483 | — | 0.650 |
| PDDL 2.1 baseline / +FS | 0.500 / 0.733 | — | **0.000 / 0.067** |

- Divergence is the headline: Planetarium+FS accepts 0.583 operationally but only 0.417
  match the reference — **0.200 accepted-but-unmatched** (p7). On PDDL 2.1 the
  accepted-but-structurally-unmatched fraction is **0.500 (baseline) and 0.667 (few-shot)**
  while structural match never exceeds 0.067 (Table 3 p7)
- Repair helps operational metrics far more than fidelity: on unsupported AutoPlanBench the
  **structural gain is negative** (-0.100 and -0.067) — the repair loop moves candidates
  *away* from the reference (p6)
- Gripper on Planetarium collapses to **0.000** final operational success at baseline,
  recovering to 0.500 with few-shot; the same domain in AutoPlanBench reaches 0.842-0.789
  (p6) — the failure is dataset convention, not domain difficulty
- **Manual audit of the LLM critic** (24 stratified outputs): agreed with human judgement in
  **13/24**; it accepted 3 unfaithful and rejected 8 faithful instances. The paper concludes
  the critic is usable as feedback but "not as an independently reliable task-faithfulness
  oracle" (p7)

## Limitations
- ⚠ "Semantic equivalence" here means **reconstruction of the curated benchmark encoding**,
  not absolute correctness; the authors say explicitly that a failed structural match "does
  not necessarily imply that the generated problem is invalid or useless" (p5). So 0.267 is
  a lower bound on correctness and 0.842 an upper bound on fidelity-to-one-encoding
- ⚠ The spread is enormous and benchmark-driven: 0.267 → 0.842 across two classical
  benchmarks with the *same* pipeline. Any single quoted percentage for "LLM PDDL semantic
  correctness" is meaningless without naming the benchmark
- Main model is gpt-4.1-mini, a small model; frontier-model runs are relegated to an appendix
- AutoPlanBench NL inputs are **template-generated from the reference problem file** (p4), so
  its high scores partly measure template inversion, not natural-language understanding
- 60 instances per subset, 10 per PDDL 2.1 domain; no CIs reported

## Relevance
- REPORT.md: this **replaces the 24-35% single-study figure taken from 2608.14590 p4**.
  Better sourcing, and it brackets that range rather than contradicting it: Planetarium
  semantic equivalence is 0.267-0.417 with the pipeline's own repairs applied, i.e. squarely
  inside 24-35% at baseline. But the report should now say *26.7-41.7% on Planetarium,
  71.4-84.2% on AutoPlanBench, and ~0-6.7% exact reconstruction on PDDL 2.1 (temporal/numeric)*,
  and attribute the spread to benchmark encoding conventions
- The PDDL 2.1 row is the sharpest single fact: once plans carry **time and numeric
  resources** — exactly the regime AI4Research's budgets and deadlines live in — operational
  acceptance rises to 0.733 while reference reconstruction stays at 0.067
- Directly supports the report's evaluator-binding argument from the other direction: the
  only online acceptance signal available without a reference is an LLM critic, and that
  critic agrees with a human **13/24** of the time (p7)
