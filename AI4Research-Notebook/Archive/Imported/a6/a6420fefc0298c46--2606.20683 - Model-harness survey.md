# 2606.20683 · From Question Answering to Task Completion: A Survey on Agent System and Harness Design

arXiv v1 Jun 2026 · 29 pp (about 22 body)
Read: body p1-22 this session (evidence sections p15-20 in full)

## Summary
The framing survey for the harness question: an LLM agent is a **foundation model
coupled with an execution harness**, and the survey asks where the bottleneck sits. It
decomposes the harness into six runtime responsibilities — observation, context,
control, action, state, and **verification/governance** — then aggregates public
leaderboard evidence showing that, with the model fixed, the harness moves SWE-bench
Verified, Terminal-Bench 2.0 and WebArena scores by 10-40 points.

## How it works (p4-15)
- Harness components: observation interface I_obs, context manager C, control loop L,
  action interface I_act, state and artifact store S, verification and governance V (p6)
- Four engineering paradigms in sequence: prompt engineering (an *expression* problem),
  context engineering (an *information* problem), **harness engineering** (feedback,
  verification loops, error recovery, sub-agent coordination), then model-harness
  co-evolution (p2, p9-11)
- Task-property → harness-response mapping (Table 5, p15): long horizon → checkpoints
  and artifacts; strong oracle → verifier loops and repair cycles; **weak or delayed
  oracle → provenance tracking, review, approval**; irreversible actions → sandbox,
  gates, rollback; high autonomy → logging, budgets, controllers
- Key structural claim: the primary bottleneck **migrates by domain** — verification and
  governance in coding, observation/action in web-GUI, **context manager and state store
  in research**, verification again in medicine, control loop in embodied (p15)
- Argues for six reporting dimensions beyond task success: reliability, efficiency,
  latency, safety, process quality (p16)

## Results (aggregated public evidence)
- **SWE-bench Verified** (Table 7, p17). Model effect within one harness: SWE-agent +
  tools 49.0% (Claude 3.5 Sonnet) → 73.2% (Opus 4). Harness effect within one model:
  GPT-4o spans 23.2% (SWE-agent) to 38.8% (Agentless); Claude 3.5 Sonnet spans 33.6%
  (SWE-agent) to 53.6% (PatchPilot); Claude Opus 4/4.5 narrows to 73.2-77.6% (p17)
- **Scaffold complexity does not predict effectiveness**: under Opus 4.5, mini-SWE-agent
  (~100 lines of Python) reaches 76.8% against OpenHands + CodeAct 2.1 at 77.6% (p17)
- Vendor (closed) scaffolds lead open ones by ~2-4% on same-generation models — Opus 4.5
  80.9% vendor vs 77.6% OpenHands; Gemini 3 Pro 76.2% vs 74.2% (p17)
- **Terminal-Bench 2.0** (p18, Table 8): fixed-model harness spreads of GPT-5.3-Codex
  64.7% (Terminus 2) → 78.4% (SageAgent), **13.7 pts**; Claude Opus 4.6 58.0% (Claude
  Code) → 76.4% (Meta-Harness), **18.4 pts**; Gemini 3.1 Pro 59.4% (Gemini CLI) → 80.2%
  (TongAgents), **20.8 pts**. Across the 20 models with ≥3 harness results, the **median
  within-model range is 13.6%** and 14 of 20 vary by ≥10% (p18)
- Operational profiles differ at equal accuracy: for Opus 4.6, Meta-Harness uses 755.0K
  median input tokens vs Terminus 2's 79.4K while cutting the timeout rate 18.2% → 7.9%
  (Table 8, p18)
- **WebArena** (Table 9, p20): harness low-to-high spans of 20.2 pts (GPT-3.5), 18.1
  (GPT-4), **41.5 (GPT-4o: 19.2 → 54.6)**, 29.2 (GPT-4 Turbo)

## Limitations (stated)
- ⚠ Table 7 is "a compact synthesis of public evidence rather than a fully controlled
  factorial experiment"; model snapshots, reasoning settings and retry budgets are not
  aligned across sources, and vendor rows are **upper-envelope references, not
  ablations** (p17). Only within-row-family comparisons are safe
- Terminal-Bench resource analysis covers only 48 of 75 public submissions that strictly
  match a visible leaderboard entry; token fields cover 45.0% of trial records and
  dollar-cost only 15.2%, so **monetary cost is excluded from cross-harness claims**
  (p18)

## Relevance
- **Report §3.3/§5**: the single best source of harness-effect numbers across three
  different benchmark regimes, and it independently confirms the Terminal-Bench figures
  the report already uses (2601.11868) by decomposing that leaderboard by harness
- Table 5's row "weak or delayed oracle → provenance tracking, review, approval" is the
  survey's own statement of the AI4Research thesis, and it places research squarely in
  the weak-oracle regime where a verification-first substrate is the correct response
- ⚠ Also the strongest evidence *against* over-engineering: mini-SWE-agent at ~100 lines
  is within 0.8 pt of OpenHands under the same model. Complexity is not the lever;
  interface design is
- Cites Claw-SWE-Bench (2606.12344) in its benchmark table as the harness-focused entry,
  confirming the two papers are the recognised pair on this question
