# SkillProbe (2603.21019): a skill's behaviour does not match its declaration

**Supports:** Verify, Remove (composition).

**Relation to CC.** SkillProbe is the closest paper to CC's verification:

- Its Alignment Detector compares what a skill **declares** with what its code **does**.
- It has to extract the declared side from prose, with regex and a model. CC has the author declare effects as
  structured data, so the comparison needs no extraction.

Read in full on 2026-09-22 (16 pages).

## What it does

- **Three phases** (Fig. 3, p7):
  1. *Gatekeeper*: admission filtering for malicious patterns, dependencies with known CVEs, and whether the declared
     permissions are reasonable. A single BLOCK from any gate blocks the skill (p7-8).
  2. *Alignment Detector*: for each skill, compares the declared capability set D(s) with the implemented set C(s).
     Each capability is a pair ⟨Resource, Access⟩ (p8).
  3. *Flow Simulator*: composition risk. Each skill gets output-risk and input-sensitivity tags, matched against nine
     source-to-sink risk-link policies. The search is linear in skills × rules rather than exponential in sets (p8,
     Table 1 p10).
- **A four-class alignment matrix** (p8):
  - Match: D = C;
  - Over-declaration: D ⊃ C, more permissions claimed than used;
  - Under-declaration: C ⊃ D, **shadow functions**;
  - Mixed.
- **The verdict** is REJECTED, CONDITIONAL or APPROVED, under a one-vote veto (p8-9).
- **Deduplication** by SHA-256 file fingerprint (p9).

## What it found

- **Top 2,500 ClawHub skills,** audited with one model (Nex-N1) (p11-12):
  - 9.9% clean (approved with no findings);
  - 59.8% approved with minor findings;
  - 30.4% conditional.

  The authors summarise this as over 90% failing rigorous admission standards (p12). The conditional share stays at
  20-35% across download tiers: popularity does not predict security (Fig. 5, p12).
- **Composition:**
  - 499 skills had at least one confirmed risk link, forming 75,373 risk edges;
  - data exfiltration and fact poisoning are about 80% of edges;
  - the high-risk subset forms **one connected component** (p12-13).
- **Other work it cites** (p5):
  - about 13% of 10,240 MCP servers have undocumented high-risk operations (Li et al. 2026);
  - 26.1% of 31,132 skills had at least one vulnerability (Liu et al. 2026b, p4).

## Limits (the authors', and ours)

- **The model changes the verdict.** Across the top 20 skills, Sonnet 4.6 marked 45% conditional and GPT-5.2-Codex 5%
  (Table 2, p10). The 2,500-skill audit used one model.
- **Extraction depends on the model's reasoning depth,** for both the declared side (prose) and the code side
  (p14 Limitations 1).
- **Composition detection** covers only the nine predefined risk policies (p14, Limitations 2).
- **No dynamic sandbox yet;** it is future work (p14).
- Findings are "security quality", not task success.

## What it gives the schema

- **Verify:** a capability's observed effects must match its declared effects, with **under-declaration (shadow
  functions) rejected**. That is `EFFECT_OUT_OF_SCOPE`, and the reason effects are declared as structured
  resource/access pairs rather than prose.
- **Verify:** declared **over**-permission is itself a finding. A capsule declaring far more than it uses widens its
  reach, which the gate can flag.
- **Pick / Remove:** composition risk is systemic, so screening by set is needed. It agrees with SkillFuzz from a
  different angle (tags and policies, not a plan search).
- **Verify:** a verdict from one judge model is not stable across models. This supports recording which verifier ran
  and measuring it (The Blind Curator).
