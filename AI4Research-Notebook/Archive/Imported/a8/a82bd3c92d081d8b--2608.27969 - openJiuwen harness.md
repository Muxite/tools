# 2608.27969 · openJiuwen: Beyond Static Harnesses for Long-Horizon Coding Agents

openJiuwen Team, Huawei Technologies · arXiv 28 Aug 2026 · 19 pp · read in full
Code: github.com/openJiuwen-ai/jiuwenswarm

## Summary
Presents openJiuwen as an open-source agent **harness** organised around 2 properties.
**Structural Composability** is the developer-facing one: every agent (standalone,
sub-agent, or part of a multi-agent flow) reuses 1 execution substrate, so scaling
the topology does not need a new engine. **Runtime Adaptivity** is the task-facing one:
the framework changes its own runtime state (context, feedback, stopping) as evidence
arrives, around a fixed model policy π, without touching model weights. Evaluated on
SWE-bench Verified and Terminal-Bench 2.1, it beats the strongest selected leaderboard
entries by 3.4 and 3.39 points.

## How it works
- **Inner Loop / Outer Loop** (§3.1.1): the Inner Loop is a bounded ReAct step loop
  (build context, call π, run tools, record observations); one full Inner Loop is an
  Outer Loop round, after which composable evaluators decide whether to continue.
  Input arriving mid-call is applied at the next boundary, never to an in-flight call
- **Rails** (§3.1.2): cross-cutting capabilities (security, memory, planning, context,
  delegation, human interaction) are ρ = (H_ρ, f_ρ, p_ρ): hook set, handler, priority.
  Ordering is explicit metadata; equal priorities resolve deterministically.
  **Visibility gating** g(ρ, u) ∈ {0,1} gives each execution subject its own capability
  set, enabling bounded recursive delegation and role isolation
- **Swarm Flow** (§3.1.3): composable multi-agent operators `budget()`, `parallel()`,
  `compact()`, `pipeline()`, `agent_session()`, `human()`, `return`. Fig. 3 builds a
  coding agent: leader reads budget → parallel candidate workers → compact → pipeline
  through review → stateful arbiter → optional human
- **Runtime adaptivity** (§3.2) framed as constrained online optimisation
  Θ_t = (κ_t, Φ_t, ι_t) (context construction, acceptance/stopping, diagnostic
  injection) with constraints C1 context budget, C2 feedback admissible before
  injection, C3 acceptance and stop limits. The objective is explicitly "conceptual",
  not solved numerically
  - **Context Management**: progressive compression m(0)→…→m(L), structure-aware
    reduction of diffs/logs before LLM summarisation, dead-loop collapse, offload to
    handles with coarse-to-fine retrieval; can share session lifecycle with KV-cache reuse
  - **Goal Mode**: Φ_t ∈ {continue, complete, blocked}, kept separate from hard caps
    g_cap; stop at T = inf{t : Φ ≠ continue ∨ g_cap = 1}. Self, independent or hybrid
    assessment behind one interface
  - **LSP-Driven Passive Feedback**: diagnostics ranked, deduplicated and capped per file
    (K_file) and in total (K_sem) before injection. Scope stated: type errors, symbols,
    static diagnostics only; says nothing about architecture or business logic
  - **Self-Reflection**: after a task, extract experience X_n = Ψ(h), update store
    E_{n+1} = U(E_n, X_n) (validate, dedupe, merge), retrieve for later tasks. Retrieval
    still passes through Context Management

## Results
- Terminal-Bench 2.1 (89 tasks): **87.19 ± 1.20** with GPT-5.6 Sol; **84.04 ± 1.12**
  with Fable 5 vs Claude Code + Fable 5 at 83.8 ± 1.2 and Terminus 2 at 80.4 (Table 1, p13)
- SWE-bench Verified (500): **82.60** with Claude 4.5 Opus vs 79.20 for live-SWE-agent
  and Sonar Foundation Agent on the same model (Table 2, p13)
- Category view (Table 3, p14): strongest on file-operations (0.76 vs 0.56 Claude Code,
  model-matched) and system administration (0.889 vs 0.778)
- By fix duration (Table 4, p15): 91.75% on <15 min, 81.23% on 15 min–1 h, 52.38% on
  1–4 h (live-SWE-agent 54.76%); >4 h bucket has only 3 tasks

## Limitations (stated)
- Leaderboard comparisons differ in prompts, tools and implementations: "system-level
  comparisons rather than controlled estimates of the contribution of the harness
  alone" (p16)
- No per-mechanism ablations; only 2 benchmarks (§5)
- Explanations for category and duration results are "plausible systems-level" factors,
  not controlled causal claims (p15-16)

## Relevance to the report
- Names **DeepSeek Harness** as a peer with "plugin-level composability" (p1-2): the two
  are alternative harnesses, not layers
- The **freeze vs runtime adaptivity** trade: "Decisions made before execution therefore
  become progressively stale" (p3) is the strongest stated case against AI4Research's
  freeze
- Goal Mode's independent assessment and separated hard caps parallel AI4Research's
  gates; Rails' priority metadata parallels declared composition order
- All numbers are **coding** benchmarks; nothing measures research work
