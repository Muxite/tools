# Audience Profile — drives every choice in the report & deck

Stated by the owner 2026-09-10.

## Who is in the room

| Who | Context on this system | Technical level |
|---|---|---|
| **Supervising SWE** (1) | High — supervises the work | Expert. Will ask hard questions. |
| **Colleagues** (2) | Onboarded **1 day** before the presentation | CS students who have done agentic AI work |
| **Presenters** (2, incl. owner) | Onboarded **5 days** before | Same floor, slightly more context |

**Minimum technical floor: CS students who have already done agentic AI work.**

So assume they know: what an LLM agent is, tool calling, prompting, DAGs,
JSON Schema, CI, git. Do **not** assume they know: this codebase, capability
capsules, contract freezing, or the research (AutoSci) domain.

## Hard constraints

1. **ENGLISH ONLY.** Not everyone reads Chinese, and much of this repo is
   Chinese (README, `harness/metadata/*`, both capsule design docs, Phase 22
   plans). **Every quoted passage must be translated.** Where a Chinese
   original is worth showing, put the English first and the original in a
   footnote or appendix — never Chinese-only in the body.
2. **The presenters have 5 days of context and must field questions from an
   expert.** The report is therefore also a *study aid*. It must build
   understanding, not just record facts — and it needs an anticipated-Q&A
   section so the presenters aren't ambushed.
3. **Two audiences at once.** The deck must not bore the supervising SWE or
   lose the 1-day-old colleagues. Technique: keep the main line accessible,
   push depth into backup slides the presenters can jump to if challenged.

## What this implies

- **Lead with a concrete worked example**, not a taxonomy. "Here is one request
  moving through nine stages" beats "here are our nine components."
- **Define every internal term on first use.** Capsule, freeze, logical vs
  physical operator, IR, trust class, journey test. A glossary is mandatory.
- **Analogies to things CS students know**: the freeze is a lockfile; capsules
  are like typed, effect-declaring function signatures; logical→physical
  operators are like an interface vs implementation; the operator inbox is a
  work queue.
- **Be explicit about what is built vs designed vs aspirational.** The
  supervising SWE will probe exactly there, and the repo's own docs contain
  substantial aspirational material (see the capsule design docs).
- **Anticipated Q&A is a deliverable**, not a nicety. Include the hard
  questions and honest answers.
