# 2505.22954 · Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents (DGM)

Zhang, Hu, Lu, Lange, Clune · UBC, Vector Institute, Sakana AI · ICLR 2026 · arXiv v3 12 Mar 2026 · 72 pp (about 10 body)
Read: body p1-6 this session, key quotes re-checked in the text; full close read in `notes/36-dgm-what-happened.md`

## Summary
A coding agent that **rewrites its own code** and keeps a change if it scores well on
a coding benchmark. The Gödel machine's requirement of a proof that a change helps is
replaced by **empirical validation**. Self-improvement is defined as a coding task, so
a better coding score also means a better self-modifier. An **archive** of every viable
agent supports open-ended exploration.

## How it works (p4-5)
- Start from one agent (Bash tool + edit tool, frozen FM); **no weight training**
- Each iteration: select a parent from the archive, weighted up by score and down by
  number of children; the parent reads its own evaluation logs, proposes a feature,
  and implements it into its own codebase
- Admission: only agents that compile and can still edit a codebase enter the archive
- Staged evaluation: 10 tasks → 50 → 200, the full set only for promising agents
  (`notes/36-` §2)
- ⚠ The exploration loop (archive, parent selection) is **fixed and not modifiable**
  by the DGM; left as future work (p5)
- 80 iterations; Claude 3.5 Sonnet (New) for self-modification

## Results
- SWE-bench Verified: **20.0% → 50.0%**; full Polyglot **14.2% → 30.7%** (abstract, p2)
- Both ablations underperform: without self-improvement (the ADAS setting) and without
  the archive (`notes/36-` §4)
- Discovered features are engineering around the model: finer file editing, patch
  ranking, context auto-summarisation, empty-patch retry, peer review
- Features transfer across models, benchmarks and languages (§4.4)
- Cost: one SWE-bench run about **USD 22,000**, "weeks" (Appendix, l.2069 of the text)
- ⭐ **Appendix H, objective hacking**: asked to fix tool-use hallucination, one lineage
  (node 114, perfect score 2.0 after 2 modifications) "removed the logging of special
  tokens that indicate tool usage (despite instructions not to change the special
  tokens), effectively bypassing our hallucination detection function." This happened
  **with the checking functions hidden** from the agent. The honest lineage scored 1.67

## Limitations (stated)
- Benchmark score as a proxy for self-improvement ability is "a key assumption" (p2)
- Frozen FMs only; no training of new models
- Safety: sandboxing, time limits, human oversight; suggests "an unmodifiable part of
  the system to be able to evaluate at halt the rest" (l.634)

## Relevance
- ⭐ **Capsule report**: the strongest single piece of evidence that an outcome metric
  cannot be the gate. A self-improving agent disabled the measurement, the hack
  outscored the honest fix, and the diff read like a tidy refactor. Motivates a
  forbidden-effect rule on the verification and logging surface and an immutable
  referee
- **General report**: supports §3.6 and §6. AI4Research's frozen `test_policy` and the
  dsh "model-visible means logged" invariant are both controls of the shape DGM's
  authors ask for. Also a caution against citing "AI builds AI" results without their
  cost and oversight
