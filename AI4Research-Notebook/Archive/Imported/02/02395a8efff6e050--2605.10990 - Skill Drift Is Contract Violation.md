# 2605.10990 · Skill Drift Is Contract Violation: Proactive Maintenance for LLM Agent Skill Libraries

## Summary
Skills in a library go stale when the packages, APIs, URLs and configs they reference change.
Existing monitors watch **values**. The paper's claim is that drift depends on the **role** a
value plays: "A version string in a comment is noise; the same string in a pinned dependency
is an obligation" (p1). A skill carries **environment contracts**, and drift is a **contract
violation** (p2). **SkillGuard** extracts contract records from the skill document, drops the
ones labelled INCIDENTAL, and matches only OPERATIONAL ones against known drift events or live
evidence. A failed contract becomes the repair prompt (p4-6). **DriftBench** has 880 pairs:
174 generated drifts, 107 real-world drifts and 599 negative controls (p2, p4). Headline:
contract-free CI probes 40% FPR vs SkillGuard 0/599. Known-drift precision is 100% on all
five backbones, recall 24-76%. Pre-registered live scan: 86% conservative precision, 55%
recall. One-round repair goes from 10% to 78% (p1, p7-8).

## How it works (p4-6, p12-14, p20)
- **Contract** C(S) = {c_i = (t_i, r_i, v_i, e_i)}: contract **type**, **role** in
  {OPERATIONAL, INCIDENTAL}, **value** to validate, **evidence span** in S (p5, Table 3 p12)
- **Drift event** d_j = (t_j, o_j, n_j, s_j): drift type, old value, new value, evidence
  source (p5, p12)
- **Roles** (p12): OPERATIONAL = "the skill relies on the value for execution or
  correctness", e.g. pinned dependency, API endpoint, schema field, auth mechanism, env
  variable, config value. INCIDENTAL = changing it does not alter behaviour, e.g. comment,
  tutorial citation, badge, documentation example. The role is **binary** and a per-record label
- **Types**: no closed contract-type list is given. Mentions refer to "packages, services,
  URLs, API paths, configuration names, credentials, schemas" (p4). The drift taxonomy has
  **8 types**: URL change, version bump, configuration change, API migration, deprecation,
  schema change, authentication change, dependency update (p3, p13). compatible(t_i, t_j)
  links contract type to drift type, but the mapping is not specified (p6, p14)
- **Extraction** (p5, p17, p20): a deterministic pass over **15 regex families** (URLs,
  version constraints, imports, API paths, auth patterns, Docker images, GitHub Actions, env
  vars, cloud regions, CLI flags, config filenames, npm @version, git branch names; about 13
  are named). Then an LLM semantic pass emits (t, r, v, e) records, including implicit ones
  (response formats, tool availability, schema fields). The two passes are merged and deduplicated
- **Order is the mechanism**: role filter **before** validation (Alg. 1, p13)
- **Matching** (p6, Table 4 p14): role gate, then type gate, then exact/substring match, then
  >=2 shared tokens, then a one-token typed backoff; otherwise reject. Normalisation is
  type-aware, with separate tokenisers for versions, package names, API paths, env vars and
  URLs (p13). It matches the **old** value o_j against v_i
- **Live mode** (p6): validates operational contracts against package registries, URL
  responses and "ecosystem conventions" when a validator exists. It is not exhaustive
- **Repair** (p6, p20): the prompt carries the skill, the failed contract, its evidence span,
  old/new values and category-aware instructions. Two candidates (temperature 0.0 and 0.2);
  the first that passes the verifier is kept. **Literal verifier**: every n_j present and o_j absent
- **Benchmark build** (p4, p13-14): 49 SWE-Skills-Bench skills. Qwen3.6-Plus proposes 6-8
  drifts per skill, giving 422 candidates and 174 kept. DeepSeek-R1 cross-validates; the
  authors adjudicate. 107 LLM-free drifts from PyPI, npm, GitHub Actions and Docker Hub
  (22 skills, 5 types). Negatives: 49 identity, 300 formatting, 250 semantic ("commentary
  versions, alias URLs, homograph values, non-breaking patches", p17)

## Results
- ⭐ **False alarms (Table 10, p17)**: 0/599 overall, Wilson 95% CI [0, 0.6]%. Per split:
  identity 0/49 [0, 7.3]%, formatting 0/300 [0, 1.3]%, semantic 0/250 [0, 1.5]%
- **Baselines (Table 11, p17)**: CI probes without contracts P 60% / R 30% / **FPR 40%**;
  Grep/diff 100/30/0; Dependabot-style 80/11/10; NL2Contract-style 100/45/0; static config
  checker 0/0/0; SkillGuard 100/76/0; canary execution 100/100/0. The canary is "simulated"
  and treated as an oracle upper bound (p7). The Fig. 3 inset puts CI probe's 40% on the
  599 negatives (p7); the n behind the baseline recall figures is not given
- ⭐ **Known drift (Table 2, p7; Table 9, p17)**: precision 100% on all 5 backbones. Recall:
  Qwen3.6-Plus **76%** [62, 88], DeepSeek-R1 62% [55, 70], DeepSeek-V3.2 57% [44, 70],
  GLM-5.1 54% [40, 69], Qwen3-235B-A22B 24% [17, 32]
- ⚠ The Qwen3.6-Plus per-type table sums to **n = 42** drifts (4+4+6+5+9+6+3+5, Table 17
  p20), with 32 detected (76%). The CI widths imply very different n per backbone (about 40
  for Qwen3.6-Plus, about 160 for DeepSeek-R1; my inference). Which split Table 2 uses is
  not stated
- **Per type, Qwen3.6-Plus (Table 17, p20)**: URL 4/4 and version 4/4 detected; API 83%,
  dependency 80%, config 67%, deprecation 67%, auth 67% (n = 3), schema 60%
- **Role-label audit (Table 8, p15)**: 200 human-labelled mentions, OPERATIONAL as positive:
  P 89.5%, R 83.4%, F1 86.3%. Semantic hard negatives: P 100%, **R 72.7%** (n = 44).
  Controlled P 81.2% (n = 43)
- **Extraction sensitivity (Table 12, p18)**: going from 7 to 15 regex families raises
  regex-only recall 13% to 33% (controlled) and 45% to 78% (real-world). Mean contracts per
  skill 3.4 to 11.7; FPR stays 0%. External untailored set: 0/7 to 7/7 (p18)
- ⭐ **Live discovery (p8, Table 13 p18)**: 49 skills, 22 drifted and 27 fresh. 14 flagged:
  TP 12, FP 2, FN 10, TN 25. Precision **86%** (12/14), recall 55% (12/22), FPR 7% (2/27).
  Both FPs were later adjudicated as genuine drift (a dbt 301 redirect, a MLflow 404) but are
  kept as FPs (p18)
- **Live-monitoring simulation (p18)**: 8/11 drifted skills detected, 0 FP among 38 fresh.
  Repair 3 skills: 38% conditional, **27% end-to-end**. Not used as the primary result
- ⭐ **Repair (Table 14, p19)**: no localisation **2/20 = 10%**; plain drift text 12/20 = 60%
  (p = 0.213); Self-refine, 3 rounds, 16/20 = 80% (p = 1.000); **SkillGuard 25/32 = 78%**;
  rewrite with full drift spec 25/32 = 78% (p = 1.000). Only no-localisation vs SkillGuard is
  significant (p < 10^-5; recomputed 1.8e-6). Cost: about 10K tokens and 1 round vs about 18K
  and 3 rounds for Self-refine (Table 15, p19)
- **Verifier (Table 16, p20)**: literal verifier 165/174 = 95% vs type-aware 168/174 = 97%.
  The gap is all in dependency update (82% vs 100%)
- **Mechanism limits (p9, Table 17 p20)**: auth repair 0/3; schema and dependency repair 40%

## Limitations
- Stated (p9, p12-13): not a verifier of skill correctness. Guarantees hold only within
  extracted contracts and available validators. Implicit, behavioural or execution-only
  assumptions are missed. Role labels are "reliable but imperfect". Live validators do not
  replace canaries. Repair does not handle mechanism-level rewrites (auth flows, coupled
  schema changes, behavioural API migrations). The literal verifier is not a semantic proof.
  The open-world study covers only 49 skills; alert fatigue and human acceptance are unmeasured.
  The matcher is deliberately conservative (p13). Repair shows localisation, not dominance (p9, p18)
- ⚠ Not stated: **Qwen3.6-Plus both generates the controlled drifts (p4) and is the
  strongest detector (p7)**. Same-model artifacts are possible; DeepSeek-R1 validation of
  pair *validity* does not address this
- ⚠ Not stated: the headline 76% recall appears to rest on about 42 drifts (Table 17, p20),
  not on the 174-pair split. The repair arms use different samples: n = 20 for no-localisation,
  plain text and Self-refine vs n = 32 for SkillGuard and rewrite (p19). So the 10% vs 78%
  comparison is across different case sets
- ⚠ Not stated: 78% repair is **conditional on detection** (25 of 32 detected). End to end
  it is 25/42 = 60% on the per-type slice (Table 17, p20). Table 17's rewrite column sums to
  33/42 = 79%, while Table 14 gives rewrite 25/32 (p19-20)
- ⚠ Not stated: single runs. No seeds or repeats are reported, and CIs are bootstrap over
  cases (p20). Every detection number depends on an LLM role pass; the role-audit backbone
  is not named and inter-annotator agreement is not reported (p15)
- ⚠ Not stated: "pre-registered" has no registry, ID or timestamp. Who froze the drift
  labels is not said (p7-8). Both FPs turned out to be real drift, so the frozen labels
  missed drift, and recall and FN counts are uncertain. The 49 "real skills" are the same
  SWE-Skills-Bench skills used to build the controlled split (p4, p18)
- ⚠ Not stated: the live simulation labels the same 49 skills as 11 drifted / 38 fresh,
  against 22 / 27 in the pre-registered study (p8, p18). Contract counts also disagree:
  "15-40 contract records, with median 22" (p5) vs mean 3.4 to 11.7 per skill (Table 12,
  p18). The second may be regex-only; this is not clarified
- ⚠ Not stated: a contract's value is a **literal**, with no range or constraint semantics.
  "Non-breaking patches" are hard negatives (p17), so the no-alarm decision on moving
  versions rests on the LLM role label or on the matcher, not on a declared allowed range

## Relevance
- **Supports**: a dependency record needs a **role** field, and filtering on it must happen
  **before** any probe. Probing every observed value gives 40% FPR against 0/599 (p7, p13, p17)
- **Supports**: each dependency record should carry its **evidence span** and **type**. The
  span localises repair: 10% to 78% (p19). The type gates matching and selects the
  normaliser (p13-14)
- **Supports**: drift events as (type, old, new, source), with the validator source recorded,
  since live detection works only where a validator exists (p5-6, p20)
- **Warns**: a literal value is too strict for moving dependencies. The literal verifier
  rejects 18 pp of valid dependency updates (Table 16, p20). Auth and schema drift need
  mechanism-level contracts, not value records: auth repair 0/3 (p20)
- **Does not address**: declared version ranges, compatibility policy, or contracts between
  skills. Everything is inferred from a skill's prose by an LLM, and no author-declared
  schema is tested
