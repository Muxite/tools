# 2602.21045 · PaperTrail: A Claim-Evidence Interface for Grounding Provenance in LLM-based Scholarly Q&A

Martin-Boyle, Leckey, Brown, Kaur · CHI '26, Barcelona (ACM), April 2026 ·
arXiv v1 Feb 2026 · 25 pp (18 body)
Read: p1-p7 (system), p10 (validation), p13-p14 (results), p18 (limitations).

## Summary
The human-factors experiment this slice otherwise lacks. PaperTrail decomposes both the
LLM answer and the source papers into claims and evidence, aligns them, and shows the user
**supported assertions, unsupported claims, and information omitted from the sources**.
26 researchers used it in a within-subjects scholarly editing study.

## How it works (p4-p7)
- Three stages: offline paper-level claim-evidence extraction (pre-extracted so the corpus
  "can be versioned and audited independently of the real-time query processing", p5) →
  real-time answer-level extraction by a **separate extraction LLM from the answerer LLM**
  (p5) → claim-evidence matching via RAG
- Claim criteria: contestable (requires evidence) and declarative (p4)
- ⭐ The final support check is **deterministic**: a fixed cosine-similarity threshold of
  0.55 flags potentially unsupported evidence, tuned on five held-out examples (p7)
- Outcome measures: TXAI trust scale, self-confidence, and **behavioural reliance as
  normalized Levenshtein edit distance** between the LLM text and the participant's edit (p2)

## Results
- Extraction pipeline validation (p10): SciClaimHunt precision 0.69 / **recall 0.62** /
  F1 0.65; BioClaimDetect precision 0.63 / **recall 0.88** / F1 0.73
- ⭐ **Trust fell significantly**: 4.22 → 3.68, t(25) = 2.61, p = .015, d = 0.44 (p13 Table 1)
- ⭐ **But behaviour did not change**: reliance 0.73 → 0.75, W = 146, p = .313; confidence
  4.27 → 4.05, p = .525; cognitive load unchanged, p = .838 (p13)
- Usability dropped significantly: 5.05 → 4.48, W = 71.5, p = .026, r = 0.52 (p13)
- In the baseline, reliance correlated with trust (r = 0.57, p < .01) and usability
  (r = 0.60, p < .05); **both correlations vanish under PaperTrail** (p14)
- More highly educated participants were *less* confident with PaperTrail (r = −0.41,
  p < .05) (p14)

## Limitations
⚠ The authors state plainly that neither reference dataset has exhaustive atomic claim
annotations — "no such gold-standard dataset exists" — so precision is underestimated and
**recall is the only realistic comparison metric** (p10). The 0.62/0.88 recall spread
across two datasets is largely a property of the reference sets, not the extractor.
⚠ n = 26, single lab session, two tasks; the authors attribute the flat reliance partly to
a learning curve and time pressure (p13).
⚠ Reliance operationalized only as edit distance, which the authors concede "may not fully
capture" engagement (p18).
⚠ Claim extraction is LLM-based at both paper and answer level; only the final support
threshold is deterministic.

## Relevance
- ⭐ **Best empirical number for LLM-based claim-extraction recall in the scholarly
  domain: 0.62-0.88** depending on reference set (p10) — and the honest framing that
  precision cannot be measured because no gold atomic-claim corpus exists. That is the
  ceiling any claim-extraction evaluation, deterministic or not, is working under
- ⭐ **Directly relevant to the provenance-vs-truth distinction**: showing users granular
  claim-evidence provenance made them trust the LLM less and change nothing about what they
  did. Provenance surfacing is necessary but demonstrably not sufficient; AI4Research
  should not claim that certifying provenance changes downstream behaviour
- Confirms the architectural separation AI4Research uses: answerer and checker must be
  different models/components (p5), and the checked corpus should be versioned separately
- Usability cost is real and significant — a claim-verdict UI makes the product worse to
  use before it makes it safer
