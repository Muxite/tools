# 2510.23601 · Alita-G: Self-Evolving Generative Agent for Agent Generation

Qiu, Qi, Wang, … Liu, Wang · Princeton, Tsinghua, CUHK, SJTU, Michigan, KCL, HKU · arXiv 27 Oct 2025 · 15 pp (12 body)
Read: body p1-9 this session; full close reads in `notes/21-alita-g-close-read.md` and `notes/27-alita-g-library-management.md`

## Summary
Turns a **generalist agent into a domain specialist** by having it build its own tool
library. A master agent runs a set of target-domain tasks several times, emits reusable
**MCP tools** from successful runs, an LLM abstracts them into parameterised primitives,
and they are stored in an **MCP Box**. At inference, tools are retrieved by embedding
similarity and run through an MCP Executor. Reports a new GAIA state of the art.

## How it works (p4-6)
- **Generation**: each task executed K times; the master agent is prompted to externalise
  sub-solutions as self-contained MCPs (code + description + use case)
- ⭐ **Curation rule (Eq. 5)**: MCPs are kept **only from runs where the task succeeded**,
  π_master(x_i) = y_i. No other check on the tool itself
- **Abstraction** by a high-capacity LLM: parameter generalisation, context removal,
  interface standardisation (FastMCP), documentation. Deliberately **no clustering or
  deduplication**, "to maximize coverage" (p5)
- **Selection**: cosine similarity between the query and description ⊕ use case
  (text-embedding-3-large), threshold τ = 0.7 or top-k (Eq. 8-12)
- Agent: Manager (Claude-Sonnet-4) + Web agent (GPT-4.1), CodeAct loop

## Results
- GAIA validation: **83.03% pass@1**, 89.09% pass@3, vs **75.15%** for the original agent
  (pass@1); mean tokens 10,394 vs 12,305, a **15.5%** reduction (p6-7)
- PathVQA 60% vs 52%; HLE 33% vs 24% (100-example samples) (p7)
- Iterations (Table 4): gains to k = 3, then a plateau (83.63% at k = 5); the paper's own
  similarity analysis shows **redundancy accumulating** as the box grows, with coverage
  falling from 1.00 to 0.51 (per `notes/21-`)
- Selection strategy (Table 3) and embedding choice matter: retrieval is fragile
  (`notes/21-`)

## Limitations
- The MCP Box is built from the **same validation set** the score is reported on
  (noted in the user's own capsule draft)
- 100-example samples for PathVQA and HLE
- No library management: no retirement, no conflict handling, no dedupe (by choice)

## Relevance
- ⭐ **Capsule report**: the reference implementation of "an agent improves itself by
  keeping a library of tools", the supervisor's stated goal. Its curation signal (task
  success) is the one 2604.00392 shows admits broken tools, which is the capsule
  report's spine
- **General report**: an example of a library-building agent with no contract layer;
  its tools enter the library with no declared effects, pre/postconditions or held-out
  test
