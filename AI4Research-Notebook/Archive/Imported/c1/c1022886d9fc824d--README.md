# setup

Installers and images for getting a Windows or Linux device ready.

```
setup/windows/    Windows installers (.exe, .msi)
setup/linux/      Linux installers, tarballs and ISOs (.run, .tar.gz, .deb, .iso)
setup/any/        runs on both: scripts, Python wheels, portable archives (create when needed)
```

Put the installer straight in the OS folder and name it with its version, like
`python-3.13.5-amd64.exe`. If a program needs several files (installer plus licence plus config),
give it a folder: `<program>-<version>/`.

**List every file in that folder's `README.md` table.** The table is how you see what's here without
opening folders or guessing what a file is, and it's the only place an unversioned name like
`ChromeSetup.exe` can say what it actually installs.

For anything where the source matters (licensed software, or a download you'd want to verify again),
add a `SOURCE.md` next to it:

```
# <program> <version>
- Source:     <official download URL>
- Downloaded: YYYY-MM-DD
- SHA-256:    <hash>
- Install:    <steps, or the silent/unattended command>
```

Get the hash with `Get-FileHash <file>` (Windows) or `sha256sum <file>` (Linux).

## Rules

- **Latest version only.** Replace the old file when you update, then clear git history when
  convenient: the old installer stays in `.git` until you do (see `../HISTORY-CLEANUP.md`).
- **Offline installers where possible.** Stub installers that download at install time are useless on
  a fresh or offline machine. The tables mark them with ⚠.
- **Watch the size.** Installers and ISOs are the biggest things in tundle and they don't compress.
  A 3 GB ISO costs about 3 GB again in `.git` for as long as its version stays in history.
- **Match the architecture** (x64 / arm64) to the machine you're setting up.
