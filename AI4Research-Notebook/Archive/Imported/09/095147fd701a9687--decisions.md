# Approved scope decisions

These decisions capture the coordination scope agreed for this planning package. Product requirements and architecture remain governed by the separately supplied confirmed PRD (4) and the [maintained full design](../../architecture/design-package/README.md).

| ID | Decision | Boundary / effect |
|---|---|---|
| CC-PLAN-01 | October alignment is against the existing 10 design tasks; it does not create 10 replacement tasks. | Coding-task identity, assignment and evidence stay in native task records. |
| CC-PLAN-02 | Deliver the bounded Compiler → Planner → selected downstream CC journey; the existing Compiler through accepted `Research_Brief.json` is component preflight evidence. | Follow the current design package and existing task register. |
| CC-PLAN-03 | RSI remains independently buildable and optional off the product hot path. | RSI design/service readiness cannot block core journey acceptance or the Oct 20 pinned Screening/ranking CC handoff. |
| CC-PLAN-04 | October CC review, handoff, verifier, benchmark and journey milestones use the existing CCs, assignments and interfaces. | Link shared resources and contracts; do not duplicate them in human planning artifacts. No generalist review is scheduled in October. |
| CC-PLAN-05 | November generalist integration is limited to Nov 2–3 and the November pool is 15 human-days across eight work items. | The listed dated work is the complete planned allocation. Reallocation requires a new explicit decision. |
| CC-PLAN-06 | November interaction study compares two feasible and three incompatible/resource-conflicting cases against the October planner; the composite study is one two-CC case. | Cases are bounded evidence, not new architecture requirements. |
| CC-PLAN-07 | Offline fusion evaluates one candidate against unchanged checks. | Candidate evidence cannot change checks, release product work, or activate a candidate. |
| CC-PLAN-08 | The Oct 16 one-shot comparison is observational and cannot establish a Spec Kit winner from current records. | Keep unknown input attribution and unavailable outcome/telemetry explicit. |
| CC-PLAN-09 | December–May topics are research windows with gates, not committed product scope. | Each window requires its own readiness and evidence review before implementation allocation. |

| CC-PLAN-10 | In-progress alignment resources have an Oct13 start; preflight retains Oct9. | These are current alignment windows, not invented original design-creation dates or additional human-day allocations. |
| CC-PLAN-11 | Architecture consumes the PRD and does not author it. | M1 post-code notes on Oct19, verifier findings Oct21–23 and post-test notes Oct28 feed M2 architecture; target readiness is Nov1, with an Oct30 conditional freeze. |

| CC-PLAN-13 | Review the cohesive generated implementation before declaring it complete. | Reuse compatible work; per-CC ports and independent checking duties are in the design package. Preserve actual observations and required evidence. |
