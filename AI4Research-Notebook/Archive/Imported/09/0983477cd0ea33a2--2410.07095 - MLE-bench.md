# 2410.07095 · MLE-bench: Evaluating Machine Learning Agents on Machine Learning Engineering

Chan et al. · OpenAI · ICLR 2025 · 29 pp (10 body)
Read: body p1-8

## Summary
75 offline **Kaggle competitions** (22 low, 38 medium, 15 high complexity; plus 7 dev)
used to measure ML engineering by agents. Each competition has its description, dataset
(often a re-made train/test split), local grading code, and a snapshot of the **private
leaderboard**, so an agent's submission can be ranked against real humans and awarded a
bronze/silver/gold medal by Kaggle's own thresholds (p2-4).

## How it works
- Agent gets 24 h, 36 vCPUs, 440 GB RAM, one A10 GPU in Docker; submits a CSV; can use a
  validation server that checks format but gives no score (p5)
- **Rules**: predictions must come from a model the agent trained (no writing labels from
  memory); no looking up solutions. A **GPT-4o log inspector** checks rule-breaking;
  **Dolos plagiarism detection** against the top 50 Kaggle notebooks disqualifies >60%
  similarity (p5)
- Scaffolds: AIDE (Kaggle tree search), MLAB (MLAgentBench ResearchAgent), OpenHands

## Results (Table 2, p6)
- **o1-preview + AIDE: any medal in 16.9%** (gold 9.4%); GPT-4o + AIDE 8.7%, + OpenHands
  4.4%, + MLAB 0.8%; Claude 3.5 Sonnet + AIDE 7.6%
- pass@k roughly doubles medals: o1-preview 16.9% → 34.1% at pass@8 (p2)
- More time helps (GPT-4o 8.7% at 24 h → 11.8% at 100 h); extra GPU does not (agents
  never used the second GPU) (p2, p7)
- Failure behaviours: invalid submissions despite a validator, runs ending in minutes,
  exhausting disk/RAM, rarely reasoning about runtime (p6)
- No positive relation between a model's familiarity with a competition and its
  performance (contamination check, p8)

## Limitations (stated)
Modified datasets and grading vs. the original competitions; agents use newer methods
than many original competitors; contamination can only be partly checked.
