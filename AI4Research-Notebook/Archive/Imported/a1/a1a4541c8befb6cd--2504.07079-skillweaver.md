# SkillWeaver (2504.07079): agents improve themselves by synthesising, practising and testing skills

**Supports:** Improve, Pick, Verify.

**Relation to CC.** SkillWeaver is a self-improvement loop that builds a library of APIs. Each API documents its
prerequisites and keeps a usage log, and selection removes APIs whose preconditions do not hold. Its own verification
("ran without an exception") was gamed. CC keeps the loop, and replaces that verification with declared checks written
by someone other than the builder.

Read in full on 2026-09-22 (40 pages). Cited by the 2026-09-15 capsule report.

## What it does

- **Three stages** (Fig. 1, §2, p2-5):
  1. *Skill proposal*: a model proposes new short-horizon skills to practise (procedural, navigational,
     information-seeking).
  2. *Skill synthesis*: an agent practises; an LLM reward model judges success; a successful trajectory becomes a
     Python API (Playwright).
  3. *Skill honing*: the API is tested and debugged, with test inputs generated by a model.
- **Each API's docstring** carries a description, the **prerequisite state of the website** needed to run without
  errors, and a **usage log** of earlier executions (p4-5, Fig. 2).
- **At use time,** an API selection module "filters only relevant APIs from the API library" and "removes APIs that
  do not satisfy pre-conditions" (p6).

## What it found

- **WebArena, 812 tasks, 160 exploration iterations per site** (Table 1, p7):
  - GPT-4o: success 22.6% → 29.8% on average (+32% relative);
  - GPT-4o-mini with GPT-4o's APIs: 9.2% → 14.1% (+45% relative in Table 1; the abstract says up to 54.3%).
- **Live websites** (four sites, 57 tasks, judged manually): 40.2% → 56.2% (Table 2, p7).
- **Synthesised versus human APIs.** Synthesised APIs matched human-crafted APIs on sites with low or medium API
  support, and were worse on sites with high API support (Fig. 3, p8).
- **Failure modes in use** (p8):
  - the agent did not identify the right API;
  - the agent chose wrong parameters.

## Limits

- **The verification was gamed.** "Called without producing an exception" counted as verified, so a malfunctioning
  API could pass by silencing its exceptions. The authors call this "a measure for evaluation having unintended
  consequences" (App. D.2.1, p34).
- **No test data** for skills that need real inputs, such as adding a collaborator (App. D.2.2, p36).
- **Setup.** Single runs, GPT-4o with temperature 0.3, one exploration budget.

## What it gives the schema

- **Improve:** self-built libraries help, and weaker agents gain from stronger agents' skills. That is why the library
  and the cold path exist.
- **Pick:** selection filters on preconditions before use. CC makes those preconditions declared and code-evaluable,
  rather than docstring prose.
- **Improve:** a usage log per skill is past performance. In CC, Bindings and `use_outcome` Findings hold it,
  separate from the Declaration, so the builder cannot edit it.
- **Verify:** "no exception" is not verification. A check must test the declared job, and must not be one the
  capability can satisfy by suppressing its own signal (the same lesson as DGM).
