# 2504.07079 · SkillWeaver: Web Agents can Self-Improve by Discovering and Honing Skills

Zheng, Fatemi, Jin, Wang, Gandhi, Song, Gu, Srinivasa, Liu, Neubig, Su · Ohio State, UVA, Purdue, CMU, Cisco Research · arXiv v1 9 Apr 2025 · 41 pp (10 body)
Read: body p1-10 this session

## Summary
A web agent explores a new website with no supervision, proposes skills to practise,
and distils successful practice into **Python Playwright functions ("APIs")** that
extend its action space. The library grows over 160 iterations per site. APIs built
by a strong model also help a weaker one.

## How it works (p3-5)
1. **Skill proposal**: an LLM acts as an automatic curriculum from screenshots, URL and
   accessibility tree; it must propose novel short-horizon skills of 3 kinds:
   procedural, navigational, information-seeking
2. **Skill synthesis**: the base agent (CodeAct over Playwright) practises the skill; an
   **LLM reward model** judges success from the task, the trajectory with screenshots and
   environment feedback; successful trajectories are turned into a function. A static
   check catches common generation mistakes and forces regeneration
3. **Skill honing**: the API is run as a unit test; for parameterised APIs the **LLM
   invents test inputs**. Debugging uses the environment and the reward model
- Each API's docstring carries a **usage log** and a **precondition** on page state; an
  API-selection module removes APIs whose preconditions do not hold (p6)
- GPT-4o, temperature 0.3, 10 steps per task

## Results
- WebArena (Table 1, p7), GPT-4o: average success **22.6% → 29.8%** (+32% relative).
  GPT-4o-mini: 9.2% → 14.1%, and with skills it beats the original WebArena GPT-4o agent
  (12.3%)
- Still below human-workflow SteP (33.0%) on average; beats it on CMS and Map
- Live websites, Online-Mind2Web subset of 4 sites and 57 tasks, **manually graded**:
  40.2% → 56.2% (+40% relative); Car site unchanged (Table 2)
- Synthesised APIs are comparable to human-crafted APIs where official API support is
  low or medium, and worse where it is high (GitLab, Map) (Fig. 3, p8-9)
- Compositional APIs emerge after enough iterations (p9)
- ⚠ The paper's relative figures are inconsistent: the abstract gives 31.8% (WebArena)
  and 39.8% (live), while §4.1 applies 39.8% to WebArena GPT-4o; Table 1 prints +45% for
  GPT-4o-mini where its own numbers give about +53% (the abstract says 54.3%). Cite the
  absolute success rates

## Limitations
- The admission signal is an **LLM reward model** plus LLM-generated test inputs; no
  held-out test of the API
- Failures in use: picking the wrong API and passing wrong parameters (p9)
- Exploration is per website; 4 live sites only

## Relevance
- **Capsule report**: an early, clean example of the pipeline propose → practise →
  distil → test, with preconditions written into the tool and used to filter selection.
  Its test step is LLM-judged, the weakness 2604.00392 measures
- **General report**: a minor citation for §3.6 (implementation). Evidence that
  tool-building helps weaker models most, as SkillDAG also finds
