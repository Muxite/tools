SAY: Main points:
- Capsules ship as pinned container images so each has a stable identity and a cgroup boundary
- A host launcher runs one capsule at a time in an authorized quiet window, checks the GPU is idle, takes the GPU lock and records device counters, kernels and host usage
- The vector is stored with the capsule version and refreshed when the version, image or driver changes
- When the machine is busy, stored vectors and per-process time shares feed the simulator capsule
- The open decision is whether the sidecar and run-capture rules allow a separate profile store
