## Summary
Targets **open-ended** data discovery: given only a dataset, variable descriptions and a
budget, produce evidence-supported claims with no target question. Names the failure
mode **overinterpretation** — a claim whose semantic strength exceeds the evidential scope
of the analyses that produced it (p1-2). The fix is an **externalised epistemic state**
(seven persistent discovery objects) consulted by two control layers: L1 frontier control
decides *where* to spend budget, L2 local adjudication decides *what can be claimed*.

## How it works (p3-5)
- Seven discovery objects: pattern, investigation, structured hypothesis set (main,
  alternatives, artifact checks, robustness checks), query, evidence record,
  investigation status, frontier state (p4)
- Loop per cycle: L1 frontier selection → investigation decomposition → experiment
  execution → L2 adjudication → state update (p5). Implemented as fixed **skill
  interfaces**, "without a learned policy or a hand-coded scoring function"
- L1 returns one of {create, attach, deepen, switch, retire, stop} from pattern
  priorities, active-investigation status, red flags, frontier saturation, budget (p5)
- L2 assigns each hypothesis an outcome ∈ {support, weaken, refute, inconclusive},
  writes investigation confidence, red flags and finalisable claims. Also records a
  **surprise signal** comparing the pre-registered `expected_effect` to the observed
  result; the authors state this "is heuristic and is not a calibrated statistical
  test" (p5)
- Budget: 40 code executions per task, no web access, Qwen3.5-plus backbone (p6)

## Results
- 40 tasks: 21 BixBench, 13 BLADE, 6 DiscoveryBench, with the benchmark question and
  target answer stripped (p5-6)
- Metrics (p6): **Evidential Support (ES)** and **Discovery Value (DV)**, each 1-5 by a
  Gemini-3.1-pro rubric judge; **HQ** counts claims with ES ≥ 4 *and* DV ≥ 4
- Table 1, Overall (p7): Ours ES 3.76, DV 3.09, 261 claims, **HQ 64 / 24.5%**; SAGA
  ES 3.80, DV 2.66, HQ 52 / 20.8%; raw agent ES **4.22**, DV 2.47, HQ 47 / 12.3%;
  OpenEvolve ES 4.78, DV 1.44, HQ 16 / 4.6%
- Pairwise claim-set preference (p8, Table 2): wins 25/40 vs raw agent, 32/40 vs
  AutoDiscovery, 40/40 vs OpenEvolve, 31/40 vs SAGA
- Human validation (p9, Table 3), 120 claims per metric, two PhD annotators:
  human–human Spearman ρ 0.860 (DV) / 0.809 (ES); **judge vs human mean ρ 0.782 (DV) /
  0.687 (ES)**, MAE 0.617 / 0.627 on a 5-point scale
- Cumulative ablation (p9, Table 4): adding the hypothesis set raises DV to 3.23 but
  drops ES to 3.18; L2 adjudication lifts the HQ *rate* to 26.8% while cutting claims to
  142; L1 restores yield (261 claims, 64 HQ)
- Persistence ablation (p10, Table 5): context-only variant keeps DV (3.27) but ES falls
  to 3.11 and HQ to 24 / 13.0% — externalised state is what preserves evidential
  constraints across rounds

## Limitations
- ⚠ **StatefulDiscovery's claims are *less* well-supported than a plain coding agent's**:
  ES 3.76 vs 4.22 for the raw agent and 4.78 for OpenEvolve (p7). The system wins only on
  the composite because it trades support for interpretiveness. A report about
  verification should not cite it as improving evidential grounding
- ⚠ **Internal inconsistency**: the intro paragraph is duplicated on p2 and the two
  copies give different headline figures — "23% more high-quality claims than the
  closest baseline" vs "6.25pp more". Both are derivable from 24.5% vs 20.8% but the
  text was not reconciled between versions
- ES/DV are LLM-judged; judge–human agreement (ρ 0.687 for ES) is materially below
  human–human (0.809), and a GPT-5.5 second judge is only reported as preserving "the
  same qualitative pattern" (p8)
- Baselines were **adapted by the authors** to the open-ended protocol (p6-7); SAGA in
  particular was reimplemented at the analysis level rather than run as released
- Backbone sensitivity is 6 tasks, no variance (p10)

## Relevance
- Confirms the report's claim that claim-level judging is done by a model: both metrics
  are Gemini rubric scores, and the surprise signal is self-described as uncalibrated
- ⭐ The ES-vs-DV split is a useful vocabulary for §4/§6: it makes "well-supported" and
  "worth saying" separately measurable, and the ablation shows the two move in
  *opposite* directions as structure is added — a quantified form of the
  generation-vs-checking tension
- Its `expected_effect` written *before* execution (p5) is a per-query preregistration
  inside the run, the smallest unit of the mechanism 2605.08956 asks for at repository
  scale; but it is used only as a heuristic cue, never as a gate
