# 2604.00392 · Beyond Task Completion: A Verification-vs.-Conformance Gap in Tool-Evolving Agents (EvolveTool-Bench)

Kaliyev, Maryanskyy · UT Austin, Uber · arXiv v2 4 Jul 2026 · 12 pp (7 body)
Read: body p1-7 this session; earlier close read in `notes/29-silent-rot-close-read.md`

## Summary
Agents that write their own tools leave **2 artifacts**: the answer and a tool library.
Task completion (TC) certifies the answer, not the library. The paper preserves the
source of every synthesised tool and replays it against a **held-out conformance suite**
for the capability it was built for. Result: **96.8% (215 of 222) of preserved tools
score C = 0.00**, while they execute cleanly and the in-session verifier raises no flag.
Named the **verification-vs.-conformance gap**; a tool that runs but is always wrong on
unseen inputs is **silent rot**.

## How it works (p2-3)
- **EvolveTool-Bench**: 99 tasks, 3 domains (data transformation, API orchestration,
  numerical), 9 sessions of 11 tasks with shared library state
- Task roles per session: seed 3, gap 2, variant 2, compose 1, regress 1, adversarial 2
- **Strict verification policy**: only tasks with a deterministic verifier count toward
  TC; the API session is excluded until its verifiers exist. Verified subset: 8 sessions,
  51 graded tasks, 79.7% coverage of graded roles (Table 2)
- 5 protocols: No-Evolution, One-Shot, EvoSkill-style, ToolMaker-style, CREATOR-style
  (all "-style" adaptations, not native ports)
- Claude Haiku 4.5, 3 seeds, 5 s sandbox, library resets per session
- **Pre-registered** contrasts, bootstrap B = 10,000, Benjamini-Hochberg correction
- Audit trace per task: tools before, used, created, reuse outcome, artifact summary

## Results
- **TC does not separate protocols**: 0.287-0.358 (Table 3). The only contrast whose
  nominal CI excludes zero runs the wrong way: CREATOR-style − One-Shot = −7.1 pp,
  CI [−13.9, −0.1], adjusted p = 0.133, not significant (Table 4, p4)
- ⭐ **Silent rot (Table 5, p5)**: none of One-Shot's 119 or ToolMaker-style's 19 tools
  has non-zero held-out correctness; 7 of CREATOR-style's 84 (8.3%) do. Mean held-out
  robustness 0.52-0.54: the tools run and return wrong values
- **Calibration**: hand-written reference implementations score C = 1.00 on all 16
  suites; the same model reaches C = 1.00 on one capability across all 3 seeds, so the
  suites are passable (p5)
- **Why TC is unchanged**: the in-session verifier scores the one input the task needed,
  inside the regime the tool was fitted to; conformance draws from the full contract
  (p5). About two-thirds of reuse calls coincide with task failure
- Sonnet trace: one tool drives session TC to **0.95** while scoring C = 0.00 (p6)
- Proposes 3 release-gate signals: **silent rot**, **reuse trap** (raw reuse up, correct
  reuse down), **regression delta** (p6)

## Limitations (stated, p6)
- One model, 3 seeds, 51 tasks; powered only for effects of about 8-13 pp
- Protocols are adaptations; no verdict on the original methods
- Library-health composite held back until conformance alignment is complete

## Relevance
- ⭐ **Capsule report**: the core evidence that the curation signal used by Alita-G and
  similar systems (task passed → keep the tool) admits broken tools, and that a
  per-tool held-out suite fixed before synthesis is the check that finds them. Its
  recommendations (p7) read as a capsule admission policy: separate artifact from task
  success, report verifier coverage, preserve artifacts, test regression, manage
  promotion and retirement
- **General report**: supports §3.6. Fixing the test before the artifact exists is the
  same principle as AI4Research sealing `test_policy` into the frozen SchedulerInput
  hash
