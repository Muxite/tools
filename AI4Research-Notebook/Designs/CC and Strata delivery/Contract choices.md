# Schema and software reuse register

**Default order.** Retain an existing AI4R contract for AI4R decisions. Carry an upstream artifact intact when its own producer and consumer already agree. Expose a projection only when an agent needs to discover or call it. Define a small local relationship when two authorities must be joined. Install a new orchestrator only if it removes more owned code and operational work than the first pilot requires.

### How to establish that reuse saves work

For each candidate, record producer file/function, consumer file/function, resolved commit or specification version, license, a real or clearly synthetic payload, the native validation command, and an incompatible payload. Then estimate the remaining work in inspectable units: new adapter entrypoints, custom fields, credential paths, persistent services and failure cases. Compare native invocation with the wrapper on the same fixture. An untested interface is “source reviewed”; only the paired run earns “behavior reproduced.” DeepSeek Superagent contributes work-item and durable outbox patterns; adopting its separate harness introduces another runtime. Use the pinned review to justify that choice. [DeepSeek source](https://github.com/deepseek-ai/dsh-superagent-prototype/tree/6337fc823ce20251c8de8085948165c81aaa701e)

### Reconcile the workshop schema before writing its successor

- **Tool/Bundle.** Map `artifacts`, `members`, capabilities and ports to the existing package, capability and digest-pinned file manifest. Preserve v2 effect ceilings, qualified scope, independent checker identity and protected targets. A name match is insufficient.
- **Experiment.** Treat this as a possible capsule kind packaging reusable procedure and checks. Keep objective authorization, concrete run, selected artifacts, host lease and result outside its reusable identity. Check whether a package referencing existing contracts expresses the pilot before adding a discriminator.
- **Lab messages.** Keep the existing call for authorized work and receipt for a checked result. Add control-plane messages only for durable transitions the current contracts cannot express, such as fenced host restore. Deduplication, epoch comparison and lease expiry are transactional rules.
- **Publish schemas economically.** Pin exact upstream schemas or native validators with sha256 and license. Cache permitted files locally and disable network reference resolution during validation. Use standard JSON Schema validators for local records. Translate across dialects only at a documented boundary. A specification page, TypeScript type, Protobuf message and JSON Schema require different validators. [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)
- **Field admission test.** Give every proposed new field a producer, consumer, enforcement point, failure example and reason existing fields cannot carry it. Remove fields that have no consumer. Preserve changed semantics with a versioned adapter and paired fixtures. Keep a single editable owner for each rule.
