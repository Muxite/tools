# One catalog interface for separate agent environments

The factory and lab have distinct policy views over the same declaration model. A factory may bind a builder and create a candidate. The lab may inspect read-only inputs, run a pinned benchmark and write attempt evidence. Discovery reflects locally eligible releases. Descriptive prose never expands a principal's grants.

1. **Index declarations.** Admission verifies identity, signer, release digest, checks and compatibility. Index the induced package/member relationships in the existing registry or PostgreSQL. Expose small summaries first. A generation number identifies the active snapshot.
2. **Filter for a real call.** Check required input/output contracts, platform and device, reader ABI, dependency/data access, allowed effects, resources and current qualification. Reject missing conditions and state what is required. Rank remaining operations by purpose and observed evidence for the target. An unavailable tool can trigger a request to the CC Factory.
3. **Bind atomically.** In one transaction check active generation, budgets and release status, pin carrier/inputs/check policy, acquire the live reference and record the call. Recheck an operation selected from a stale list. MCP projection is one consumer. A stable discover/invoke pair avoids dependence on whether a harness refreshes dynamic tool listings.
4. **Execute and observe.** Stage content by digest, start an isolated process or invoke the registered native binding, validate typed output and collect the receipt. Retry only under the declared effect/idempotency policy. Join the receipt to release, scope, target and check version.
5. **Withdraw and drain.** Publish a new generation; new binds cannot select the withdrawn release. Allow ordinary in-flight calls to finish with their existing pins; immediately revoke/fence them when policy requires emergency cancellation. Reclaim only after all live, evidence, rollback and shared-content references clear. A reinstalled revision gets a fresh binding and review.
6. **Demonstrate it through the actual session.** In one running JiuwenSwarm session list, install, invoke, pause a call, withdraw, reject a new call, finish the paused call and install a successor. Confirm the session ID persists and the tool identity changes. Repeat with an incompatible reader and denied effect. The supplied local validator exercises a reference model; target integration remains open.

**RSI example.** If storage improves but decode falls below its floor, the agent can inspect a reconstruction trace, ask for a different reader, propose a recipe change or close the branch with a negative finding. Each new bound action records its evidence dependencies. Fixed warmup and scoring protect comparability across branches. Only the evaluation service sees hidden inputs. Promotion requires the independent receipt and a reviewed source or recipe change.
