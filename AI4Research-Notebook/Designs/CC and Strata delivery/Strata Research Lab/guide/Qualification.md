### Hardware qualification record to fill during the first reservation

- **Before provision.** Capture machine identity, OS, kernel, GPU driver/runtime, free disk, storage backend, cgroup support, idle MemAvailable, active services, host reserve, GPU access controls and temperature/clock telemetry availability. Stage signed native engine, image manifest, exact model shard digests and benchmark fixtures. Fail early on any missing essential probe.
- **Start and contain.** Demonstrate ARM64 executable, GB10 visibility through the approved boundary, host-side quota enforcement and denied outbound IPv4, IPv6 and peer routes. Exercise gateway-permitted staging; check the resulting receipts and denied direct publication. Record a negative lease on a busy host.
- **Measure.** Use one exclusive host and identical qualified software/driver for both arms. Set explicit shared-memory headroom, scratch and a two-hour maximum per the current brief. Disk admission must account for both products and scratch overhead. Verify native inference API and router parity separately. Record source provenance and sample rates; declare sensor gaps explicitly.
- **Break and recover.** Stop the candidate in the middle of an arm. Snapshot or quarantine partial data and confirm lease fencing before replay. Rerun with the original workload and clean outputs; check validation, output retrieval and cleanup out of band.
- **Draw the deployment boundary.** If approved Incus+Docker GPU nesting fails, leave that host profile unqualified. Evaluate a dedicated host with reviewed image launch and externally enforced networking under a separately documented profile. The Mac CPU VM and any native Metal build each need their own probes. The portable artifact references and evaluator receipt format survive these provider changes.
