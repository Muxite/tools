# Producing attachable Obsidian design folders

Deliver two folders with clear boundaries. The vault keeps one editable owner per contract. Export versioned copies with hashes and relative links so either folder can be attached on its own. The common files in each export must be byte-identical projections of the same owner.

| Proposed folder | Human-required route | Agent-reference route |
|---|---|---|
| Capability Capsules and Factories | Start here; a Strata example; package versus capability versus run; CC Factory intake and qualification; Software Factory assembly and rebuild; discovery, install and withdrawal | Schema catalog, pinned native contracts or licensed snapshots, adapter mapping, compiler inputs/outputs, fixtures and acceptance matrix |
| Research Labs | Start here; fleet placement; control/data plane sequence; host versus agent authority; monitored gateway; failure, checkpoint and restore; evidence to RSI | Binding, lease and evidence interfaces, state transitions, provider-specific constraints, positive/negative fixtures and acceptance matrix |

**Entry page requirement.** A person gets one annotated system picture and a five-minute reading route. An implementer gets the first executable slice, dependencies, a reproducible validation command and explicit gaps. Each boundary page names caller, callee, payload, authentication, failure, retry, durable owner and evidence of completion. Put file excerpts next to the behavior they control.

### Scoped assignments for agents

| Contributor | Inputs and exclusive write scope | Return condition |
|---|---|---|
| Integration editor | Meeting directions, M2a stage and previous deck. Own glossary, authority map, cross-folder interface IDs and decision log. | One Strata trace with an owner for every transition and a delta for the in-lab AI4R change. Resolve conflicting meanings before parallel authors extend them. |
| CC owner | Package, capability, checks and both factories. Own capsule folder and schema mappings. | Given a pinned source, show generated candidate, rejected incompatible release, pool admission, built engine and a new release after dependency change. |
| Lab owner | Approved interface IDs and confirmed threat model. Own lab folder. | Trace staged artifact to resource claim to agent call to evidence. Show duplicate delivery, stale epoch, denied egress, failed stop and restart. List the Mac CPU and native Metal qualification boundaries. |
| Source and benchmark owner | Pinned Strata and Superagent sources, existing source review. Own evidence ledger and test fixture provenance. | For each reuse claim identify a real entrypoint, accepted input, emitted record, license and evidence limit. Label paper claims, code observations, upstream measurements and local measurements separately. |
| Slide author | Approved example, decisions and ledger. Own deck source and presenter notes. | Render the short feature story, cite the exact sources and flag mismatches back to the appropriate owner. |
| Independent reader | A clean copy of each exported folder plus the deck. Own findings only. | Identify the first place a fresh implementer has to guess. Cite file, ambiguous field, impact and proposed correction. Owner resolves it or records a named blocker. |

One person can take several assignments. Use one task card per contribution: **decision needed, permitted files, must-read sources, inputs from others, expected artifacts, explicit exclusions, acceptance case, current blocker**. Each reply should report changed paths, evidence and outstanding decisions. Integration editor controls shared objects. Contributors propose changes to another owner by reference. Avoid asking every agent to reread the whole vault or research every sandbox technology.

### Release checks

1. Validate old and proposed fixtures with their named validators; include unsupported hardware, wrong digest, missing quality evidence and a stale lease. Check cross-file references and semantic conditions separately. File validation and hardware evidence have distinct status.
2. Walk a baseline and one failed candidate end to end. Match capsule, release, input pack, attempt, benchmark and receipt identifiers in both folders. Verify the example does not quietly grant publication or network permission.
3. Copy each export to an empty directory. Validate links, embedded diagrams, headings, schemas, fixtures, local references, hashes and test commands offline. Record any external binary or hardware prerequisite up front. A source bibliography may be online; mandatory contract bytes must travel with the attachment where redistribution is permitted.
4. Ask a fresh reader to describe exactly which files to implement first, what to reuse and what a failed acceptance looks like. Any necessary decision they invent returns to its owner.
5. Update the vault design index and relevant owner notes in one reviewed change. Keep the exact request and hash separate from the interpretation. Mark superseded routes with a link and date; retain original snapshots. Rebuild exports and slide excerpts after contract edits. Run the vault checker, review the focused diff, then record the feature PR and open/close owner in the M2 plan.

**Completion evidence.** Track PASS/FAIL/NOT RUN/BLOCKED against specific scopes: schema shape, offline package, upstream reference replay, single-Spark lab qualification, paired comparison and RSI rebuild. A field validated against a schema cannot stand in for an experiment.
