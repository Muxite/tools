# A practical guide to making a presentation about a topic

## 1. Decide what the audience should understand

Before drafting slides, write one sentence for the audience and one sentence for the change you want: understand a result, accept a design, compare alternatives, or choose a next step. Record what they already know, the time available, and the questions they will need answered.

Make the whole talk one connected argument. Write its conclusion early; choose the evidence needed to support it; arrange the slides so each point makes the next one easier to understand. If the deck accompanies a report, carry over its evidence and qualifications while adapting the sequence for speech.

## 2. Build a simple story

Use a compact outline: context or problem → why the current approach is insufficient → key idea → how it works → evidence and limitations → recommendation or next step. Remove sections that do not move the audience through this argument.

For each slide, write the one thing the audience should remember. Make the headline state that takeaway when practical. Use one main visual or claim per slide; add only enough explanation to make it understandable. Use section markers to orient a long technical talk.

## 3. Give evidence a visible place

Put the result, figure, comparison, or workflow on the slide when the audience needs to see it. Cite the source near the claim in readable text. Put method, caveats, detailed citations, and expected questions in speaker notes when the audience does not need them on the screen. Distinguish measured results, estimates, proposals, and open questions.

Build a short claim/evidence table before making results slides. Check that each number, comparison, and causal statement is supported by the cited source. Explain what an experiment actually tested. Never turn a design hypothesis or an unrun test into a measured result.

## 4. Draw the material

Choose the format that makes the point easiest to grasp: workflow for sequence, architecture diagram for interfaces, chart for quantitative comparison, table for a small set of alternatives, and a short excerpt for a precise contract. Label figures so they can be read without a spoken explanation. Use consistent color to encode the same meaning throughout.

Use the available canvas to show useful content. Replace oversized empty areas with an informative diagram, plot, comparison, or larger readable text. Preserve margins, alignment, and space around individual elements. Avoid decorative elements that obscure the evidence.

## 5. Rehearse and check the finished deck

Estimate time from the actual spoken script. Rehearse aloud and cut material or move detail into notes if the talk runs long. Render the actual presentation, inspect every slide and the deck at normal viewing size, then fix crowding, empty areas, overlap, small labels, weak contrast, inconsistent layouts, and unsupported claims. Run the source format’s linter when one exists.
