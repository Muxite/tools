# Presentation review checklist

Record each item as **pass**, **change made**, or **not applicable with reason**. Link the rendered draft and source version.

## Argument and evidence

- [ ] Audience, purpose, and requested action are clear.
- [ ] The deck makes one coherent argument; every section supports it.
- [ ] Each content slide has one main point and a clear takeaway.
- [ ] Numbers, quotations, diagrams, and comparisons trace to sources.
- [ ] Measured, source-reported, inferred, proposed, and unresolved claims are distinguishable.
- [ ] Limitations are visible where they change interpretation.

## Design and whitespace

- [ ] Main point and visual hierarchy are clear at presentation size.
- [ ] Large empty regions have a purpose or have been used to enlarge helpful content.
- [ ] The design retains margins and space around individual elements.
- [ ] Charts and diagrams are labelled and understandable without tiny text.
- [ ] Crowded slides were split or simplified, not solved by shrinking text.
- [ ] Color, contrast, alignment, and layout are consistent and accessible.

## Build and delivery

- [ ] Source-of-truth file and build path are recorded.
- [ ] Native lint/build checks pass; outstanding warnings have a reason.
- [ ] The built deck was rendered and every slide inspected.
- [ ] Contact-sheet rhythm and repeated layouts were reviewed.
- [ ] Speaker notes support delivery; the timing was rehearsed.
- [ ] The shown deck, source, figures, evidence, and review record are archived together.
